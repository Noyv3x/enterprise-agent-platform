# Business and project plan template

Write in the user's language (Chinese by default for Chinese requests). Keep it
as long as the work needs; a one-week campaign gets one page, a migration or a
launch gets sections below in full. Prefer tables for owners, dates and budget.

```markdown
# <计划名称 / Plan title>

## 1. 目标与成功标准 / Objective and success measures
One-sentence objective. 3–5 measurable outcomes (metric, baseline, target, date)
and how each will be measured. State what "done" means.

## 2. 背景与现状 / Context
What exists today, with sources (documents, figures, links). Constraints:
deadline, budget ceiling, policy, staffing, dependencies on other teams.

## 3. 范围 / Scope
In scope. Out of scope (explicit). Stakeholders and approvers.

## 4. 方案与取舍 / Approach and alternatives
Chosen approach and why; main alternatives rejected and the reason; key
assumptions (each with how it will be checked).

## 5. 工作分解与里程碑 / Workstreams and milestones
| # | 工作项 | 负责人 | 开始 | 完成 | 依赖 | 交付物 / 验收 |
Owners are roles or names the user gave; if unknown write "待指定".

## 6. 资源与预算 / Resources and budget
| 项目 | 数量/工时 | 单价 | 小计 | 依据(来源 or 估算方式) |
Mark every estimate as an estimate. Totals must add up; show currency and tax basis.

## 7. 风险与应对 / Risks
| 风险 | 可能性 | 影响 | 预警信号 | 应对 / 负责人 |

## 8. 沟通与评审节奏 / Governance
Status reporting cadence, decision points, who approves what, escalation path.

## 9. 待决事项与所需信息 / Open decisions and data needed
Questions the user must answer; numbers or documents still missing.
```

Rules: no invented numbers, dates, names or approvals; dates are relative to
the user's stated start unless given; keep legal, compliance and financial
statements to what the sources say and flag items needing professional review.
Check that milestone dates respect dependencies and that budget lines sum to
the total. If a table is the main object, a CSV or XLSX companion can be offered
afterwards; do not create it unasked during plan mode.
