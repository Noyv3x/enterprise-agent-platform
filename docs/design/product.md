# 产品设计

本文定义当前产品边界。系统结构见[系统架构](system-architecture.md)，Agent 行为见 [Agent Runtime](agent-runtime.md)，安全前提见[安全与信任边界](security-and-trust.md)。

## 产品目标

平台面向彼此可信的小规模成员，为每位用户提供私人 Agent，并在共享频道中提供频道 Agent。系统将对话、文件、工作环境、会话、记忆、技能和浏览器状态按主 Agent 分开，同时允许 Agent 为单次操作显式使用宿主机能力完成真实工作。

每个私人 Agent 和频道主 Agent都有独立持久工作目录与 Sandbox 容器，委派子 Agent共享父环境。Sandbox 用于环境隔离和减少误操作，不是恶意多租户安全边界；显式宿主执行可以获得部署用户及其免密 sudo 权限，接受这一信任风险是部署前提。

## 角色与权限

平台内置管理员、经理、成员和只读四组权限组合。服务端权限判断是唯一授权边界，前端隐藏入口只用于改善体验。

- 管理员负责账号、模型授权、运行时、自动更新、Telegram、审计和系统设置。
- 经理可管理频道和知识库，并使用私人及频道 Agent。
- 成员可参与频道并使用私人 Agent。
- 只读用户只能读取被授权的频道和知识内容。

账号还可以分别保存显示名称、职位、模型选择、思考深度、时区和启用状态。Agent 提示词必须携带当前说话人的可用上下文，并使用管理员配置的 Agent 展示名称，但不暴露内部框架、Runtime 或模型供应商实现。

## 品牌配置

产品不绑定固定展示品牌。新部署默认产品名为 `Agent Platform`、Agent 名为 `Agent`、使用组件库默认主色且不显示 Logo；管理员可在部署后的管理面板修改产品名、Agent 名、主色和单一 Logo。品牌值对全体用户生效，产品名用于浏览器界面，Agent 名用于 Agent 自称与回复通知；它们不是新的身份、权限或提示词指令来源。

登录前页面可以读取同一份公开品牌投影。公开投影只包含当前名称、主色、Logo URL 和单调 revision，不包含其它 Platform 设置。Logo 由 Platform 保存并通过同源只读端点返回；不接受远程图片 URL。Manager 在 Platform 不可用时展示中性维护文案，不把动态品牌复制成第二份控制面配置。

## 对话模型

私人 Agent 和每个频道主 Agent 都是长期逻辑身份，拥有稳定工作区和可轮换的会话生命周期。逻辑身份可以先于首次执行登记；只有受认证更新提交可把旧基线遗留的未物化工作区补齐，普通启动不会静默修复缺失目录。私人消息按进入顺序持久化；同一用户连续发送的相关短消息可并入正在运行的回复，并保留每条消息的处理状态。频道消息、私人消息和 Agent 回复都保存在平台消息库中。用户可以撤回自己已经发送并持久化的频道消息；撤回只改变频道中的可见性，不取消已经排队或运行的 Agent 回复，也不删除 Runtime 历史、附件或审计数据。

界面只在发生工具调用时展示工作记录。工作过程先展开显示在当前回复顶部，最终输出开始后自动折叠；没有工具调用时不创建空工作记录。审批请求是工作过程的一部分，但必须保持为明确、可操作的独立状态。

## 核心能力

- 频道、私人对话、附件、输入合并、流式回复和上下文用量查看。
- 账号、权限组、频道、私人消息和 token 用量管理。
- 平台内建的共享语义知识库；支持结构化录入以及 TXT、Markdown、CSV、JSON、HTML、PDF、DOCX、XLSX、PPTX、ODT 文件批量导入和原件下载，向量由管理员配置的 OpenAI-compatible Embeddings API 生成，未配置时该能力明确禁用。
- 自动维护的 Agent 记忆、用户资料记忆、跨会话搜索，以及最终回复后的低优先级学习复盘。
- 每 Agent 技能包，包括只读预置技能、用户技能和只维护 Agent 自建技能的自动改进闭环。
- 私人 Agent 的一次性、间隔和 cron 计划任务。
- 基于 Camoufox 的浏览器工具、低帧率预览和受控的人类接管。
- 运行中终端的只读预览。
- 每主 Agent 独立、可停止后重建且保留工作目录/HOME/环境的 Sandbox。
- 仅面向私人聊天的 Telegram Gateway。
- 私人 Agent 的 IMAP/SMTP 邮箱管理，以及带每账户/每私人 Agent 积压上限、有界预览和可恢复去重的收信唤醒。
- 回复完成时的浏览器系统通知，以及默认关闭、可显式开启的可信局域网入口。
- Codex OAuth 与 Grok OAuth；不提供模型 API key 产品入口。
- 等待空闲后执行、全程阻断使用并可失败回滚的自动更新。

详细集成语义见[外部集成](integrations.md)，数据所有权见[数据、记忆与会话](data-memory-sessions.md)。

## 界面范围

浏览器界面支持简体中文、English 和繁體中文。i18n 只约束界面文字，不翻译用户消息、Agent 输出、文件内容、工具输出或日志。响应式布局必须使用完整可用视口，在手机、平板和桌面上都不能依赖固定桌面宽度。

浏览器与终端预览属于聊天界面的侧栏内容。没有打开的浏览器 tab 或运行中的终端时，不显示相应侧栏按钮；资源存在但首帧仍在加载时，应显示加载态，而不是误报“尚未运行”。浏览器允许用户在明确接管期间协助处理验证码或卡住的页面，终端始终只读。前端细则见[前端设计](frontend.md)。

## 明确不做

- 不把 Agent Sandbox 宣称为恶意多租户安全边界。
- 不将 Firecrawl 或 Pi 作为可直接修改的产品代码。
- 不让终端预览成为可交互的远程控制入口，也不允许浏览器接管越过当前用户、scope 或 tab 的授权边界。
- 不让 OAuth 在线发现绕过 Runtime 的模型能力目录。
- 不在界面之外扩展本轮 i18n 范围。
