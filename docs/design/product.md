# 产品设计

本文定义当前产品边界。系统结构见[系统架构](system-architecture.md)，Agent 行为见 [Agent Runtime](agent-runtime.md)，安全前提见[安全与信任边界](security-and-trust.md)。

## 产品目标

平台面向彼此可信的小规模成员，为每位用户提供个人 AI，并在平台成员可见的公共频道中提供频道 Agent。系统将对话、文件、工作环境、会话、记忆、Skill、MCP 配置和浏览器状态按主 Agent 分开，同时允许 Agent 为单次操作显式使用宿主机能力完成真实工作。“公共”只表示具备工作区读取权限的平台成员都能看见，不表示匿名互联网公开；发送仍要求聊天权限。

每个个人 AI 和频道主 Agent都有独立持久工作目录与 Sandbox 容器，委派子 Agent共享父环境。Sandbox 用于环境隔离和减少误操作，不是恶意多租户安全边界；显式宿主执行可以获得部署用户及其免密 sudo 权限，接受这一信任风险是部署前提。

## 角色与权限

平台内置管理员、经理、成员和只读四组权限组合。服务端权限判断是唯一授权边界，前端隐藏入口只用于改善体验。

- 管理员负责账号、模型授权、运行时、自动更新、Telegram、审计和系统设置。
- 经理可管理公共频道，并使用个人 AI 及频道 Agent。
- 成员可参与公共频道并使用个人 AI。
- 只读用户可以读取公共频道内容，但不能发送消息。

账号还可以分别保存显示名称、职位、模型选择、思考深度、时区和启用状态。权限组只用于授权与管理界面，不作为头像旁姓名的副标题；姓名下有职位时只显示职位，无职位时留空。Agent 提示词必须携带当前说话人的可用上下文，并使用管理员配置的 Agent 展示名称，但不暴露内部框架、Runtime 或模型供应商实现。默认回复使用用户正在使用的语言和大白话：先说结果，句子简短，避免套话、官话、无意义标题和重复；用户明确要求的语气或格式仍优先。

## 品牌配置

产品不绑定固定展示品牌。新部署默认产品名为 `Agent Platform`、Agent 名为 `Agent`、使用组件库默认主色且不显示 Logo；管理员可在部署后的管理面板修改产品名、Agent 名、主色和单一 Logo。品牌值对全体用户生效，产品名用于浏览器界面，Agent 名用于 Agent 自称与回复通知；它们不是新的身份、权限或提示词指令来源。

登录前页面可以读取同一份公开品牌投影。公开投影只包含当前名称、主色、Logo URL 和单调 revision，不包含其它 Platform 设置。Logo 由 Platform 保存并通过同源只读端点返回；不接受远程图片 URL。Manager 在 Platform 不可用时展示中性维护文案，不把动态品牌复制成第二份控制面配置。

## 对话模型

个人 AI 和每个频道主 Agent 都是长期逻辑身份，拥有稳定工作区和可轮换的会话生命周期。逻辑身份可以先于首次执行登记；只有受认证更新提交可把旧基线遗留的未物化工作区补齐，普通启动不会静默修复缺失目录。个人消息按进入顺序持久化；同一用户连续发送的相关短消息可并入正在运行的回复，并保留每条消息的处理状态。公共频道消息、个人消息和 Agent 回复都保存在平台消息库中；Agent 在工作区生成的文件由 Platform 将规范逻辑交付标记转换为当前消息的结构化附件，界面不直接信任或解析正文路径。用户可以撤回自己已经发送并持久化的公共频道消息；撤回只改变频道中的可见性，不取消已经排队或运行的 Agent 回复，也不删除 Runtime 历史、附件或审计数据。

认证用户进入产品后的默认会话是自己的个人 AI；只有账号没有个人 AI 权限时才回退到第一个可读公共频道。公共频道仍是显式导航目标，不能因为频道存在就覆盖个人 AI 默认入口。界面必须持续强化公共频道的成员可见属性，避免用户把它误认为个人对话。

个人 AI 的权威消息历史加载完成且确认为空时，每次登录会话最多自动展示一次初始使用引导；加载中、加载失败、已有消息、乐观发送或 Agent 活动时不得误弹。引导说明每个个人 AI 和频道主 Agent 都有自己的电脑与文件工作区，可以处理和交付文件、控制网页，并可在自己的工作区安装 Skill 和 MCP 集成。引导里的「电脑」三项文案锁定为简体中文「一台自己的电脑」、English “Its own computer”、繁體中文「一台自己的電腦」；这里的「工作区」只表示该 Agent 可长期保存文件的目录，不是应用外壳导航的「工作区 / Workspace / 工作區」。侧边栏提供永久的再次打开入口；每项“试试”只把本地化示例填入当前个人 AI 的空草稿，不自动发送，也不覆盖已有草稿。

个人 AI 的 Agent 回复头像旁不显示“个人 AI”作者名，只保留时间、生成状态和消息操作；公共频道仍显示频道 Agent 的展示名。

界面只在发生工具调用时展示工作记录。Run 工作期间以无展开控件的紧凑进度行显示在当前回复顶部；Run 完成或失败后自动收起，入口文案为“查看 AI 工作过程”，用户主动展开后才查看工具间阶段性说明，并逐条打开有实质证据的详情。详情必须优先回答“做了什么、作用于什么、得到什么结果”：文件操作显示唯一一次路径及有界结果，命令显示完整脱敏命令和终端输出，搜索显示查询与命中，浏览器和其它工具显示安全动作对象及结果或错误。工具名、状态和时间只是辅助元信息，不能单独构成一个可展开详情，也不能在行头和详情里机械重复占用空间。工作记录来自当前 Run 的单一顺序时间线：阶段性说明与工具首次调用按真实发生顺序出现，同一工具的完成或失败只更新原行。正常记录完整保留；异常事件流触发安全上限时明确展示被省略的事件或字符数量。没有工具调用时不创建空工作记录。审批请求是工作过程的一部分，但必须保持为明确、可操作的独立状态。

## 核心能力

- 公共频道、个人对话、附件、输入合并、流式回复、上下文用量查看，以及不进入模型或产品消息的本地 `/compact` 会话压缩命令。Agent 发送的 XLSX、DOCX、PPTX 和 PDF 在聊天内提供同源只读预览，其它附件仍只提供下载。
- 账号、权限组、公共频道、个人消息和 token 用量管理。
- 自动维护的 Agent 记忆、用户资料记忆、跨会话搜索，以及最终回复后的低优先级学习复盘。
- 每主 Agent 独立的工作区 Skill 与 MCP 配置。用户 Skill 位于 `/workspace/.agent-platform/skills/<skill-id>/`，MCP 清单位于 `/workspace/.agent-platform/mcp.json`，本地 MCP 包位于 `/workspace/.agent-platform/mcp/<server-id>/`；平台按调用重新读取这些文件，无需重启。只读预置技能、用户技能和只维护 Agent 自建技能的自动改进闭环继续存在；预置文档技能覆盖表格、文字文档、演示稿和 PDF，用户要求交付此类成果时优先生成并发送经过结构、内容与视觉质量检查的美观真实文件，而不是用 Markdown 伪装文件产物或直接交付库的机械默认样式。
- 个人 AI 的一次性、间隔和 cron 计划任务。
- 当前 Run 可见工作的实时「电脑」画面：默认是吸附在输入框上方一角的迷你 16:9 画中画，画中画从本轮工作开始按秒显示已用时间；点击后在既有右侧预览槽展开为竖屏，并让当前屏幕占满标题栏以下的可用区域。画中画与竖屏都优先展示当前模式的真实有界内容。Codex OAuth 的文件写入/补丁在模型流式生成工具参数时显示明确标为未提交的有界草稿，工具开始后继续沿用该草稿，成功或失败时再收敛到正式工作区快照或错误；其它路径仍只展示已读取快照。终端复用实际只读日志并为短命令补齐最终输出，浏览器复用 Camoufox 低帧率画面与显式接管，搜索工具显示有界结果列表，Agent 写出的 HTML 页面可在同一槽位沙箱呈现。
- 每主 Agent 独立、可停止后重建且保留工作目录/HOME/环境的 Sandbox。
- 仅面向私人聊天的 Telegram Gateway。
- 个人 AI 的 IMAP/SMTP 邮箱管理，以及带每账户/每个人 AI 积压上限、有界预览和可恢复去重的收信唤醒。
- 用户可按外部平台提供的 Skill/MCP 安装说明自行接入 Sylver Lining 等服务；平台不内置特定服务商连接器、账号绑定页或固定业务工具。
- 回复完成时的浏览器系统通知，以及默认关闭、可显式开启的可信局域网入口。
- Codex OAuth 与 Grok OAuth；不提供模型 API key 产品入口。
- 等待空闲后执行、全程阻断使用并可失败回滚的自动更新。

详细集成语义见[外部集成](integrations.md)，数据所有权见[数据、记忆与会话](data-memory-sessions.md)。

## 电脑与用语

用户可见的「电脑」是当前对话里 Agent 正在做的可见工作的实时投影，不是一台独立操作系统，也不是应用外壳里的导航分区。

锁定界面用语：

- 侧栏标题：简体中文「AI 的电脑」、English “AI computer”、繁體中文「AI 的電腦」。个人 AI 与公共频道主 Agent 使用同一组词，不把频道 Agent 写成「个人电脑」。
- 画中画与展开入口的悬停/无障碍名称：简体中文「显示 AI 的电脑」、English “Show the AI computer”、繁體中文「顯示 AI 的電腦」。
- 既有动作仍用既有词：工作记录是「查看 AI 工作过程」，浏览器协助是「接管」，终端与文件/搜索画面是只读「预览」。不要用 live / 实时桌面 / 操作系统 作为产品名。

内部词不得提升为这组界面文案：`Sandbox`、`/workspace`、宿主、`host`、Runtime、Pi、Firecrawl、Camoufox、`/compact`、学习复盘、`private` / `channel` scope。导航「工作区 / Workspace / 工作區」继续只表示应用外壳，不能改名或暗示它就是 AI 的电脑。

「自己的电脑」只表示每个主 Agent 有一份稳定文件目录和一份当前工作投影。它不表示加密存储、恶意多租户隔离或不能使用宿主/`sudo`、不能浏览内网。Sandbox 仍是减少误操作的环境隔离，不是安全边界；部署前提见[安全与信任边界](security-and-trust.md)。

## 电脑画面

个人 AI 和公共频道主 Agent 共用同一套电脑画面。它只投影当前 scope 里已经发生的可见工作，不发明新的 Runtime 工具，也不把记忆、Skill、MCP 配置、定时任务、邮件或 `/compact` 说成操作系统功能。

默认形态是聊天输入框上方靠右吸附的迷你 16:9 画中画，而不是铺满聊天列的横幅。它只占一个小播放器的视觉面积，与输入面保持短间距，不覆盖输入控件、消息正文或“跳到最新”等操作；窄屏下继续缩小但保持 16:9。当前 Run 活动时，画中画以 `started_at` 为单一时间基准每秒更新已用时间；Run 结束且画中画因呈现页等资源继续保留时不再把历史页面伪装成仍在计时。画中画应显示当前文件、终端、浏览器、搜索或呈现页的紧凑真实画面，资源尚未出现时才显示骨架。没有当前可见的电脑工作、也没有可呈现的 HTML 页面时，空闲对话不显示空白监视器；公共频道空闲时仍只保留技能等既有侧栏入口。点击画中画或侧栏电脑入口时，复用既有右侧聊天预览槽，展开为一块竖屏，标题为「AI 的电脑 / AI computer / AI 的電腦」；标题栏以下只保留必要的模式内工具栏，当前文件、终端、浏览器、搜索或呈现画面必须填满其余可用高度，滚动发生在画面内部，不能退化成抽屉顶部的一张矮卡片。记忆、技能和定时任务继续是侧栏上的独立项，占用同一互斥抽屉；浏览器与终端不再各占一个实时入口，而是作为电脑画面里的两种屏幕。

当前可见工具决定屏幕：

- `read_file` / `write_file` / `patch_file`：有界文件文本。只读取当前 Agent 工作区里的文件；宿主目标只显示路径与状态，不把宿主正文拉进画面。Codex OAuth 固定的 Responses 路径可以把模型已经输出、经过有界脱敏的 `write_file.content` 或 `patch_file.new_text` 投影为「未提交草稿」；草稿不是工作区文件、不能用于审批或执行，补丁草稿必须说明它只是替换片段，不能冒充完整文件。画面应把已经取得的权威草稿字符连续、平滑地追赶到最新版本，而不是每隔数千字节或在同一动画延迟点整块出现。创建工具刚开始而文件尚未原子落盘时继续显示草稿或等待并重试，工具完成后必须读取同一路径的最终快照；修改文件不能停留在修改前正文。其它模型路径和 `read_file` 只呈现 Platform 实际返回的快照，不根据进度标记、参数长度或动画伪造正文。
- `terminal` / 运行中或 `orphaned` 的进程：既有只读终端预览。终端主体显示脱敏命令、真实有界 stdout/stderr 和结束结果，工作目录等信息退居终端标题；短命令若在首轮进程预览前结束，使用同一工具工作项的有界最终结果补齐画面，不能退化成参数列表。
- `browser`：既有 Camoufox 截图画面；默认只读，接管仍须明确手势。
- `web` / `search_files`：有界结果列表，不是可打开的文件管理器。
- 呈现页：Agent 向当前工作区写出 `.html` / `.htm`，或成功回复里已有 HTML 附件/`MEDIA` 路径时，同一槽位用沙箱 iframe 渲染该页。本版本不新增 Runtime 呈现工具。

画中画只在「当前 Run 有可见电脑工作」或「存在可呈现页面」时出现。资源已确认存在但首帧、日志或正文仍在加载时显示骨架，不能误报“尚未运行”或把创建中的 404 显示为永久失败。浏览器接管、终端只读、文件/搜索有界文本和 HTML 沙箱规则见[前端设计](frontend.md)与[安全与信任边界](security-and-trust.md)。

## 界面范围

浏览器界面支持简体中文、English 和繁體中文。i18n 只约束界面文字，不翻译用户消息、Agent 输出、文件内容、工具输出或日志。响应式布局必须使用完整可用视口，在手机、平板和桌面上都不能依赖固定桌面宽度。

电脑画面、浏览器协助和终端预览都属于聊天界面的侧栏内容。没有可见电脑工作且没有可呈现页面时，不显示电脑入口；记忆、技能、定时任务的显示条件不变。资源存在但首帧或正文仍在加载时，应显示加载态，而不是误报“尚未运行”。浏览器允许用户在明确接管期间协助处理验证码或卡住的页面，终端、文件和搜索画面始终只读；HTML 呈现页不得获得与产品页相同的源、Cookie 或父页面 DOM。前端细则见[前端设计](frontend.md)。

## 明确不做

- 不把 Agent Sandbox 宣称为恶意多租户安全边界，也不把「AI 的电脑」宣传成加密磁盘或不可达宿主/`sudo`/内网的隔离舱。
- 不将 Firecrawl 或 Pi 作为可直接修改的产品代码，也不把它们写进用户可见的电脑文案。
- 不为本版本新增 Runtime 呈现/桌面/窗口管理工具，不把记忆、技能、定时任务收进电脑画面，也不在浏览器与终端之外再增加第三块独立实时屏。
- 不在空闲对话放置空白监视器，不把窄屏覆盖层做成常驻桌面列，也不提供会话回放、持久电脑主页或可交互 PTY。
- 不把 Codex 文件参数草稿推广成所有供应商的兼容推断，不把未执行或未提交的草稿写入工作记录、消息、Runtime session、workspace 或备份，也不改变文件工具的原子提交语义。
- 不让终端预览成为可交互的远程控制入口，也不允许浏览器接管越过当前用户、scope 或 tab 的授权边界。
- 不让 OAuth 在线发现绕过 Runtime 的模型能力目录。
- 不在界面之外扩展本轮 i18n 范围。
