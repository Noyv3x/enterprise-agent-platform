# 前端设计

本文定义浏览器界面的结构和交互不变量。产品行为见[产品设计](product.md)，后端与 Runtime 关系见[系统架构](system-architecture.md)。

## 技术与发布边界

前端使用 React、TypeScript、Vite 和 Ant Design 6。可编辑源代码位于 `enterprise-agent-platform/frontend/`；`enterprise_agent_platform/static/` 是可重现的构建产物，只能通过前端构建脚本生成，不进入 Git 源码树。Quality 从 lockfile 干净安装依赖、拒绝 high 级别漏洞，并从前端源码重建和验证资产；新披露的传递依赖漏洞只更新受影响的 lockfile 节点，不借机升级无关组件。Platform 容器构建再把同一输出覆盖进 wheel。

构建脚本在同一文件系统的暂存目录中完成 Vite 构建、资源完整性验证、压缩和原子发布。带 hash 的依赖先安装，`index.html` 最后提交。发布清单只声明当前构建资产；提交当前入口后必须删除所有不在当前清单中的受管文件，不保留上一代 bundle，也不提供跨 generation 的静态资源兼容层。

前端数据类型以当前 API 实体名为唯一公开名称。不为已删除的规格名、旧组件名或旧响应形状保留未使用的 type alias；跨层名称改动与 API 类型在同一变更中完成。

## 品牌与部署定制

仓库发布中不绑定部署方品牌。未配置时，界面使用中性的 `Agent Platform` 产品名、`Agent` 助手名、纯文字标识、中性主题色和中性 favicon；Logo、浏览器标题、描述、通知标题与公开错误页不得退回到源码中的部署方名称或图片。管理员可在部署后热更新产品名、助手名、主色和一个通用 Logo，保存后无需重启即可作用于登录、启动恢复、前端更新提示、错误边界、应用侧栏、浏览器标题与描述和回复通知。Manager 在 Platform 离线时独立提供的灾备页只承诺中性基线，不依赖业务数据库中的动态品牌。favicon 本轮只使用仓库内置的中性图标，不把通用横向 Logo 误作方形图标，也不提供未进入服务端契约的独立图标上传。品牌名称是管理员提供的纯文本，不随界面语言翻译；围绕名称的说明和状态文案仍由三语 i18n 提供。

公开 `GET /api/platform/branding` 返回 `{schema_version: 1, revision, product_name, agent_name, primary_color, logo_url}`；管理员 `GET /api/system/branding/config` 读取同一快照，`PUT /api/system/branding/config` 以 `{expected_revision, product_name, agent_name, primary_color}` 更新文本与颜色。名称在去除首尾空白并 NFC 规范化后必须为 1–64 个 Unicode 码点，拒绝 Unicode `C*` 类别及 `U+2028/U+2029` 行段分隔符；服务端校验为最终权威，前端使用同一规则即时提示。Logo 通过管理员 `PUT /api/system/branding/logo` 的 `{expected_revision, mime_type, data_base64}` 上传，通过同一路径的 `DELETE` 和 `{expected_revision}` 删除；每次成功写都返回新快照，revision 冲突返回 `409`。前端只接受服务端返回的同源、版本化 `/api/platform/branding/logo?v=<revision>`，上传只接受 PNG/WebP、不超过 256 KiB，不把资产写入或复制进静态发布目录。静态构建只携带中性入口；旧的固定 Logo 是受管陈旧资产，下一次原子发布必须清除。

`BrandingProvider` 位于 i18n 内侧、主题、维护门、错误边界与 Store 外侧，使匿名登录、启动失败、更新维护、渲染错误和认证后界面共享同一品牌状态，且登出或 Store reset 不会清空品牌。Provider 首次渲染可从当前 origin 下的已验证公共缓存恢复 last-known 快照，同时并行使用 ETag 重验证；缓存缺失或损坏时使用中性默认值，网络请求失败时保留当前已验证快照（没有快照才保持中性默认），不能阻塞登录。管理员保存响应经过单调 revision 栅栏：只接受比当前 revision 更新的快照；同 revision 仅允许内容完全相同的幂等结果，旧 revision 或同 revision 异内容均不得覆盖 Context 或持久缓存。

跨标签页 `storage` 事件只表示权威品牌可能变化，事件携带的 `newValue`（包括合法快照）永远不直接应用，也不得因旧值、同 revision 冲突、删除或损坏值而回写 localStorage。Provider 对同一品牌 key 的连续事件去抖后发起一次不带缓存 ETag 的公共 GET，并以请求发起时的 Context 作为基线；每个请求带递增序号，只有最新仍在途请求可提交结果。这样服务端 revision 从 8 回滚到 3、随后推进到 4，以及缓存删除或损坏时都由服务端权威状态收敛，不会出现两个标签页互相恢复旧缓存的 ping-pong。

公共 GET 另需处理 Manager 回滚数据库后服务端 revision 合法降低的边界。请求发起时记录当前 revision 和完整内容；响应返回时若 Context 仍与该基线完全相同，则本次合法 `200` 作为当前服务端权威快照，可以接受较低 revision；若请求期间 Context 已被管理员保存或跨标签页同步推进，则该响应重新进入单调栅栏，旧 revision 不得覆盖较新的本地结果。这样既阻止“保存 revision 8 后旧请求 revision 7 回写”的竞态，也不会让浏览器永久卡在回滚前的高 revision。

公共品牌 `200` 响应必须先完整验证结构、名称、颜色和同源版本化 Logo URL；非法 `200` 且 Context 仍等于请求基线时，代表当前权威响应不可安全使用，必须清除本地快照及 ETag 并立即降级为中性默认值。若请求期间 Context 已推进，迟到的非法响应不得清除或重写新状态。ETag 只有精确等于当前快照 revision 的 `"branding-<revision>"` 时才可持久化并在后续请求中作为 `If-None-Match` 发送；缺失或不匹配的 ETag 不影响使用合法快照，但不得缓存，下一次必须无条件重验证。`304` 只有在请求携带了与已验证缓存 revision 精确匹配的 ETag 时才可复用缓存，否则按请求失败处理。管理保存成功后立即将返回快照送入同一 revision 栅栏并写入无 ETag 缓存；保存失败（包括 `409`）必须重新读取管理员品牌快照，同时更新 Store 和 Branding Context，确保表单与全局界面回到服务端权威 revision。

文档语言、标题与 description 由品牌和 locale 的统一 metadata 效果更新，中性 favicon 由静态入口声明；i18n 层只负责语言选择，不能再以固定产品名覆盖 metadata。Logo 保持原始比例并使用 `object-fit: contain`，不使用反色滤镜篡改上传图片；缺失或加载失败时显示可访问的品牌文字。内部 storage key、DOM 事件、通知 tag 和下载文件名使用稳定的中性命名空间，不能从可变品牌名派生，也不能保留部署方品牌作为技术标识。

## 组件与视觉系统

Ant Design 是整个浏览器界面的组件和交互语义基础，负责按钮、菜单、表单控件、表格、标签、状态、提示、空态、加载态、弹窗、抽屉和响应式数据展示。全局 `ConfigProvider` 位于 i18n 与主题 Provider 内侧，统一品牌色、字号、圆角、密度、深浅主题和组件 Token。平台不得复制组件库内部 DOM，也不得以自研基础组件重新实现同类能力。现有业务 i18n 仍是产品文案的唯一来源；`zh-CN`、`en`、`zh-TW` 只映射到对应的 Ant Design 组件语言包。

### Apple 风格界面基线

当前界面以 Apple 平台的克制、清晰和直接操作感为视觉参考，但不复制 Apple 的品牌资产、图标或产品界面。部署品牌主色和当前蓝灰中性色调保持不变；重构只调整层级、材质、字体、几何、留白和动效，不用新的高饱和色替代部署品牌色。

视觉层级遵循以下契约：

- 页面背景、主内容面、浮动面和临时覆盖层只使用四级语义材质。桌面端侧栏、顶栏、Composer 和浮层可使用低强度透明与背景模糊；不支持模糊、移动端低带宽模式或 `prefers-reduced-transparency` 时必须回退到不透明材质。正文不放在低对比玻璃层上。
- 圆角使用固定语义阶梯：紧凑控件、标准控件、内容容器、主级容器和胶囊；不在业务页随意新增半径。阴影只表达真实层级，常驻内容卡使用发丝线或极弱阴影，抽屉、弹窗和菜单才使用浮层阴影。
- 排版优先使用系统 UI 字体和 SF 兼容等宽字体栈。大标题使用紧凑字距和高于正文的字重，不再混用编辑风格衬线标题。次要文字可降低强调，但仍必须满足可读对比度。
- 应用内主操作使用部署品牌色；既有登录分屏保留其蓝灰主操作色，不用高饱和品牌色改变原有观感。一个视觉区域最多一个高强调操作。次操作使用中性填充或透明按钮，危险色只用于危险语义。悬停、按下、焦点和忙碌状态必须同时有非颜色反馈。
- 动效使用快速响应、平缓收束的统一时间曲线，只说明层级、位置和状态变化。不为装饰让常驻内容漂浮、缩放或循环。`prefers-reduced-motion` 时停用位移、缩放和非必要过渡。

全局视觉所有权必须可追踪：`AntDesignProvider` 只管理 Ant Design 组件 Token；`design-system.css` 是布局、材质、几何、排版和动效变量的唯一 CSS 真源；`platform-components.css` 只管理平台共享组合组件；路由级 CSS 只管理该业务页的特有结构。不再从多个全局文件重复定义同一 Token、Shell 或 Ant 组件外观，也不以新的末尾覆盖层修补旧规则。

应用外壳在桌面端以稳定侧栏、轻材质顶栏和单一主内容面建立层级；移动端保留同一信息顺序，但改用全宽内容和组件库抽屉。聊天正文是主角，Agent 回复优先使用无外层气泡的清晰排版，用户消息使用有界容器；Composer 作为靠近底部的单一浮动输入面，附件、文本与发送操作必须对齐，不再以贯穿整页的重边界工具栏表现。管理、设置和知识页共用同一页头、分区容器、紧凑表格/列表和抽屉编辑模型，不通过嵌套多层卡片表达层级。

通用交互必须使用组件库语义，包括登录、应用外壳、聊天输入与审批、知识库、设置、记忆、Skills、定时任务、电脑画面/预览侧栏和管理面板。聊天气泡、工具工作过程、电脑画中画、浏览器画面、只读终端、沙箱 HTML 呈现页、品牌导航等产品特有结构可以保留定制布局，但其中的按钮、输入、菜单、提示和状态仍使用统一基础组件。组合组件可以承载业务信息层级，不得自行重做焦点管理、键盘操作、加载状态或危险操作确认。

产品图标必须具有稳定的默认尺寸；未显式指定尺寸时统一使用 `18px`，不能依赖浏览器对无尺寸 SVG 的默认宽高。组件库 semantic class 应直接约束图标节点，并覆盖其嵌套节点兼容形态，避免菜单、卡片和导航因图标退化为替换元素默认尺寸而变形。

`.btn`、`.icon-btn`、`.card`、`.modal`、`.empty`、`.spinner` 和普通原生表单不属于有效设计系统；不得保留无消费者规则或对应的自研基础组件。业务 CSS 只负责页面结构、内容排版和产品特有视觉，不以高优先级选择器覆盖组件库内部节点。应用主题上下文是深浅主题的唯一状态源，并映射为组件库的默认/暗色算法；桌面采用紧凑但可读的密度，触屏目标不得低于 44px。

聊天 Composer 的自动增长 textarea、mention option 和隐藏文件 input 属于输入状态机的一部分，需要维持中文 IME、caret、焦点和分会话附件恢复，因此可以保留原生节点，但必须使用统一 Token、可访问性语义和组件级回归测试。Composer 的 textarea 必须以 `min-width: 0` 填满附件按钮与发送按钮之间的剩余宽度；两侧按钮固定在输入框首尾，单行时形成自然基线，多行时随输入框底边对齐，容器左右留白保持对称。桌面可以使用紧凑按钮，粗指针设备的附件与发送触控目标不得小于 44px。知识 Embeddings 配置表单使用组件库的标准表单、密码输入、数字输入、状态和错误语义，不保留任意 `.env` 字段编辑器。知识创建抽屉同时提供手工录入与组件库 Upload/Dragger 文件导入；支持多选、逐文件状态、总字节进度、失败原因和可取消上传，上传请求不设总墙钟超时但保留服务端空闲超时。知识卡片和正文查看器提供同源下载动作，下载文件名来自服务端 `Content-Disposition`。除 Composer 的明确边界外，文件选择使用组件库 Upload 语义，不能再新增原生交互控件。

组件库进入全局应用入口后必须保持按组件和按路由拆包。管理、知识库、设置、记忆、Skills、定时任务等非当前视图继续延迟加载，其业务 CSS 由对应的懒加载入口导入并跟随路由 chunk，不得回收到 `main.tsx`；构建产物不能为了缓存而强制聚合未使用模块。每次全局基础组件变更都要核对入口 preload、首屏 gzip 体积和慢链路下的加载反馈。

## 应用外壳

Provider 层次必须保持以下职责：

1. i18n 和主题提供全局展示上下文。
2. Branding 在主题、维护门、错误边界和 Store 之外提供公共部署品牌并维护 document metadata。
3. `UpdateGate` 在登录、Store、Toast 和应用错误边界之外处理强制维护。
4. Error Boundary 隔离业务界面错误并提供安全重载。
5. Store 只在正常产品生命周期中创建。

未登录和启动恢复界面不得静态拉入聊天、电脑画面、浏览器预览与终端预览代码；认证后的 `AppShell` 在 bootstrap 确认存在用户后延迟加载，并在慢链路下载期间复用启动加载反馈。

导航、内容区、聊天预览侧栏和移动端遮罩由 App Shell 管理。路由是客户端视图状态，不引入第二套 URL 授权模型；每个数据请求仍由服务端鉴权。

## 状态与数据访问

前端使用自有 external store 和 `useSyncExternalStore`。Selector 必须返回稳定引用；不得在 selector 内直接创建新的 `[]`、`{}`、`map()` 或 `filter()` 结果。派生默认值应在 selector 外使用模块级常量或 memo 化处理。

所有普通 HTTP 请求通过统一 `api()` 入口：

- 同源 Cookie 自动携带；
- 401 统一使当前会话失效；
- 维护响应立即触发 `UpdateGate`；
- 账号切换会取消旧账号未完成请求并使用 generation 拒绝迟到结果；
- 普通请求、SSE 和后台轮询采用不同生命周期，各自的恢复边界由前端请求实现与测试约束；它们不复用 Agent Runtime 的空闲或 terminal 超时。

带附件的消息使用同一认证和维护语义的专用 XHR 上传边界。上传不设置固定墙钟超时，调用者取消、登出、账号 generation 变化、更新切换和服务端配额仍可终止；进度只依据浏览器 `upload.progress` 的已发送/总字节展示。更新中断上传属于可重试网络/维护失败，不能在客户端静默当成已提交。上传完成到服务端保存与排队之间显示“处理中”，不能把 100% 字节误报为消息已提交。上传的 active 计数、XHR 事件和调用方 AbortSignal 监听必须由同一个终止路径释放，`send()` 同步抛错、网络错误、取消与正常完成都不能泄漏状态。

初始登录态通过紧凑 bootstrap 一次获取用户、频道、活动 scope、消息和 Agent 状态。后续资源按视图惰性加载；频道切换和 Agent 状态读取必须使用 scope/version fence，防止旧响应覆盖新界面。

管理面板的模型下拉和 OAuth 卡只消费 Platform 返回的当前 OAuth 账号安全交集，不在前端复制模型 ID、版本排序、退役名单或兼容表。OAuth 卡将交集第一项明确标为“推荐模型”，并同时展示可用模型数量；未完成 OAuth 或没有成功目录时不展示 Runtime 候选。用户明确保存的当前模型与推荐模型是不同语义，界面不得因目录刷新自动提交或覆盖前者。Runtime 模型下拉提供值为 `""` 的“自动（当前推荐 …）”选项；只修改并发、超时等其它字段时仍提交空值，不能把用于显示的推荐候选写成显式选择。账号模型下拉的“系统默认”先显示部署级明确选择，仅在部署级也为自动时显示当前推荐。

bootstrap 的默认活动 scope 是当前用户的个人 AI；只有服务端确认账号没有个人 AI 权限时才使用第一个可读频道。前端初始 Store、缓存恢复和加载失败回退不得在认证完成前短暂选中频道，也不能用本地频道默认值覆盖服务端返回的私人 scope。

浏览器界面的产品术语固定为简体中文“公共频道 / 个人 AI”、English “Public channels / Personal AI”、繁體中文“公共頻道 / 個人 AI”；内部 `channel`、`private`、`private_agent` 和历史消息作者哨兵不随展示名改变。公共频道标题必须在主侧栏使用更高对比度、成员可见说明和群组图标，当前公共频道的顶栏标题旁还要保留明确的“公共”徽标；移动端隐藏副标题后也不能丢失该标识。

个人 AI 的使用引导挂载在应用外壳，而不是会被移动侧栏销毁的子树。只有当前个人消息 history 已建立、资源不在 loading/error、消息与乐观发送均为空且 Agent 不活动时，才在本次登录会话自动展示一次；关闭后切换视图不能反复弹出。侧边栏永久保留“个人 AI 使用指南”入口，并通过正式个人视图导航动作打开。引导的“试试”只在当前个人草稿的文字与附件均为空时填入本地化示例并聚焦输入框，不调用发送接口；已有任何草稿内容必须保留并给出提示。

数据层只导出存在真实调用者的 selector、loader 与 action。页面级加载由资源键对应的细粒度 loader 组合，不保留无人调用、会重复拉取整个管理面板的聚合入口；保存 Runtime 配置后只刷新 Runtime 与 OAuth 目录。提及列表只来自 bootstrap 快照。账号权限组只使用服务端目录，不用前端写死的组表。公开更新探针只接受契约中的 `state`，不能用 operation `phase` 顶替。聊天和通知导航必须继续复用正式 action，而不是以遗留 convenience export 绕过状态隔离。

用户显示名、职位、时区和频道名由界面编辑，但不因出现在 Agent 上下文中而成为高优先级指令。后端必须把这些可变字段序列化到闭合的不可信数据块；前端校验只负责交互与长度，不是提示词安全边界。

## 实时对话

聊天使用 scope SSE 获取消息、输入状态、工具过程、审批和最终输出，轮询仅作为恢复补充。乐观消息必须带本地身份，并与服务端消息按稳定游标合并。初次加载返回最新一页；用户向上查看时使用互斥的 `before_id` 游标加载更早消息并去重 prepend，SSE/`after_id` 前向游标继续独立推进。分页请求必须捕获发起时的 scope、`before_id`、prepend 版本、唯一请求代号和服务端必填的 `reset_revision`；缺少 reset revision 时不得 prepend。清空、隐藏、切换 scope、新全量快照或同边界的新分页请求使旧请求失去所有权后，迟到的旧页和它的清理动作都必须丢弃，不能把已隐藏消息重新插回，也不能清除新请求的 loading 状态。前端不得用固定 100 条切片静默丢弃已经加载的历史；prepend 必须保持滚动视觉锚点且不增加未读计数。

已持久化的本人频道用户消息在消息操作区提供“撤回”，私人对话、他人消息、Agent 消息、系统消息和仍在乐观发送的消息不显示该入口。操作使用组件库确认浮层；服务端成功后立即从当前列表与缓存移除，并继续以 `reset_revision` 和 scope SSE 让其它标签页或客户端收敛。失败时保留原消息并显示明确错误，按钮在请求期间不可重复提交。撤回不表现为取消 Agent 任务或清除模型上下文。

离开后返回已经缓存的聊天 scope 时，必须先同步恢复该 scope 的消息、前向游标和历史分页状态，再以同一前向游标执行 delta refresh；不得随后发送无游标的“最新一页”请求并用其覆盖已加载的更早页。只有从未加载过的 scope、明确失效的 cache，或服务端 `reset_revision` 已改变时，才允许用最新页建立新的全量边界。频道、私人对话以及从系统通知进入 scope 都必须复用同一正式导航动作；任何入口都不得只改 `activeView`/`activeChannelId` 而跳过旧 scope 缓存、目标 scope 恢复、消息隔离和加载。

聊天 Markdown 支持 GFM 以及以 `$...$` 表示的行内数学、由各自独占一行的 `$$` 围住的块级数学，并使用 KaTeX 同时输出可见排版和 MathML 辅助语义；普通文本中的字面美元符号使用 `\$`。公式解析与渲染跟随懒加载的消息正文模块，不进入未登录首屏；块级公式在窄屏只允许自身横向滚动，不能撑宽消息或页面。原始 HTML、远端图片和不安全 URL 的既有边界保持不变，KaTeX 的可信命令功能必须关闭；未知命令、未闭合的流式公式或其它无效输入不得使消息树崩溃，应保留为可读源码或有界错误文本。

个人 AI 对话中，Agent 消息头像旁不渲染作者名；公共频道继续显示频道 Agent 展示名。导航、空态和输入提示仍使用“个人 AI / Personal AI / 個人 AI”。

工作记录只反映可见工具事件：

- 没有工具调用时不显示工作记录；
- 工具开始后，工作过程固定在当前回复顶部，并以类似消息网关进度行的紧凑列表实时追加；每个工具只占一条生命周期记录，默认只显示工具、单行摘要和状态；
- 当前 Run 的工作过程以单一、严格递增 `sequence` 的时间线为准；阶段性 Agent 说明在其结束边界占一条，真实工具在首次出现的位置占一条，后续生命周期只能按 `tool_call_id` 原位更新，不能因完成时间与其它同秒事件重排；
- Run 仍在工作时紧凑列表保持可见且没有收起、展开或详情控件，最终输出开始流式出现也不能提前把它折叠；
- Run 完成或失败后，持久工作记录自动收起并提供可键盘操作的展开控件，控件文案为“查看 AI 工作过程”；用户展开时间线后，只有具备脱敏参数、结果、错误或阶段性正文等实质内容的记录才提供单条展开控件，仅有工具身份、状态或时间的记录不可展开成空详情；
- 单条详情使用工具族语义组织信息而不是固定键值表：文件把操作与唯一路径作为标题并优先显示有界正文/结果，terminal/process 首屏就是完整脱敏命令与终端输出，搜索优先显示查询和命中，浏览器及其它工具优先显示安全动作对象和结果或错误。状态由时间线图标和行文案表达，起止时间只作为末尾次要元信息；同一路径、工具名和状态不得在一条详情中重复出现；
- 工具之间已经展示给用户的 Agent 阶段性说明必须与工具事件按时间顺序持久化到同一工作记录，完成后随工作记录一起折叠；最终答案仍作为独立消息正文显示，当前最终输出不得在工作记录中重复；
- 阶段性说明进入时间线后，Platform 必须清除对应的 finalized stream buffer，运行中只由紧凑工作列表展示一次，不能同时再生成完整 Agent 消息气泡或累积第二份无界副本；前端仍可读取升级前状态中的 finalized `stream_messages`，但新状态只用 `stream_message` 承载当前实时正文；
- terminal 必须展示经服务端安全处理后的完整命令参数，不能只显示工具名；
- 重复、匿名或内部工具噪声应合并，审批状态不得重复显示。
- 合法 Run 的完整时间线不得用“只取最近若干条”静默裁掉。Platform 仅为抵御异常事件流设置 512 条过程项、单项 32 KiB 详情和全部详情 512 KiB 的硬界；超过边界时必须在原位置或时间线末尾保留可见的截断标记以及省略事件/字符计数，不能伪装成完整记录。

自动记忆与 Skill 学习复盘是不可见的内部 durable worker，不属于用户当前回复，也不得生成聊天消息、输入中状态、工作记录、完成通知或伪造的工具事件。即使未来状态流意外收到 `learning.review.*` 生命周期行，前端也只能继续按真实 `tool`/`tool.started`/`tool.completed` 事件建立工作记录。

Runtime 的机械完成守卫把 Run 终结为 `needs_review` 时，Platform 保存一条明确标为未完成/需复核的 Agent 消息：正文先展示有界的最后真实阶段性说明，再展示独立 blocker，metadata 保留本轮真实 `agent_work`。界面不得把该消息套用成功完成样式或完成通知，也不得从其中的 `MEDIA:` 文本生成附件；附件仍只来自成功回复的结构化 `message.attachments`。

上下文详细信息入口只展示最新已完成回复的上下文占用，不混入供应商、内部 Runtime 或其它诊断信息。

普通文件附件显示文件名、类型、大小和下载动作。附件的唯一界面数据源是 Platform 返回的结构化 `message.attachments`；前端不从流式工作过程或消息正文自行解析 `MEDIA:`。HTML 附件可以成为电脑画面的呈现页来源，但聊天卡片仍只提供下载，不增加第三套 HTML 预览卡。当前可在聊天卡片预览的交付文档是 XLSX、DOCX、PPTX 和 PDF：卡片右上角固定提供展开与下载两个图标按钮；内嵌区域只展示服务端返回的有界首屏内容，展开后在组件库弹窗中查看同一次预览响应。XLSX 显示有界工作表表格，DOCX 显示段落文本，PPTX 按幻灯片分页显示可见文本，PDF 按页显示已有文本层。Platform 对空或通用二进制媒体类型使用自身维护的确定性后缀映射，覆盖上述四种格式，不依赖容器操作系统的 MIME 数据库；同一读边界也规范化历史附件，使既有消息无需数据迁移即可获得预览入口。预览加载、空内容、截断和失败都有明确状态，失败不能影响原文件下载。前端只把服务端返回的纯文字段或单元格字符串作为文本渲染，不解析公式、不执行宏、不把 PDF 或 Office 原件交给浏览器解析器，也不引入第二套 Office/PDF 渲染库。

Composer 支持可发现的本地斜杠命令：输入 `/` 时显示当前可用命令，首个版本只注册无参数的 `/compact`。命令建议保持 `listbox`/`option` 语义和输入框焦点行为，其中的可点击项使用统一组件库按钮，不引入原生控件例外。提交该命令不会创建用户消息、乐观消息、失败重发记录或 Agent Run，也不会把命令文本发送给模型；Platform 在当前对话空闲时请求 Runtime 立即压缩当前 session，并以本地化结果提示报告是否实际省略了历史。命令带附件、带参数或对话仍有排队/运行任务时保持草稿并明确拒绝，未知斜杠文本仍按普通消息处理。

## 电脑画面

`ChatView` 继续把 `MessageList` 与 `Composer` 包在 `ChatPreviewSidebar` 内。电脑画面复用这一右侧聊天预览槽和 `ChatPreviewContext`，不新增第三块实时屏，也不把记忆、技能、定时任务收进电脑。侧栏 52px 轨道仍承载：私人 scope 的记忆、任意 scope 的技能、私人 scope 的定时任务，以及至多一个电脑入口。浏览器与终端不再各占一个轨道按钮。

用户可见名称锁定为三种语言的完整 key：侧栏标题「AI 的电脑 / AI computer / AI 的電腦」；画中画、轨道按钮与展开动作的 tooltip/aria 为「显示 AI 的电脑 / Show the AI computer / 顯示 AI 的電腦」。不要用导航「工作区 / Workspace」或内部 `Sandbox` / `/workspace` 做这组文案。个人 AI 与公共频道共用同一组词。

### 画中画与展开

默认电脑入口是输入框上方靠右吸附的迷你 16:9 画中画，位于聊天列内、`Composer` 之上，不是工作记录旁的第二枚缩略图，也不是与 Composer 同宽的独立横幅。桌面尺寸保持在小播放器量级，窄屏继续缩小；容器只占自身尺寸，不覆盖输入框、消息或“跳到最新”，并与 Composer 的内容宽度右边缘对齐。当前 Run 活动时，画中画从权威 `agent_status.started_at` 起以 `HH:MM:SS` 或 `MM:SS` 每秒更新一次已用时间；计时变化不得重新建立预览轮询或重置播放器内容，非 live 的历史呈现页不显示仍在跳动的计时。点击画中画或电脑轨道按钮，把既有右侧预览槽展开为竖屏电脑；该手势只打开只读画面。电脑抽屉标题栏以下的 body 不再保留卡片式外边距，`ComputerScreen` 与当前模式占满其宽高，文件/终端在自身画布滚动，浏览器和呈现页按可用高度缩放；警告和必要工具栏只占固有高度，不能把主画面压回一张矮卡片。浏览器接管仍须展开后的明确「接管」按钮，不把画中画点击重新解释为一次性接管。宽屏布局仍是聊天 | 轨道 | 380–640px 抽屉；`≤1200px` 抽屉改为覆盖层，不能当成稳定桌面列；`≤520px` 全宽覆盖层继续让聊天区和轨道暂时 inert，焦点进入关闭按钮，关闭后回到原触发器，若触发器已消失则回到 Composer。

画中画只在当前 scope 存在可见电脑工作或可呈现页面时出现。空闲且无呈现页的对话，包括只有技能入口的公共频道，不得渲染空白监视器。当前 Run 一旦出现电脑类工具（文件读写/补丁、终端/进程、浏览器、`web` / `knowledge` / `search_files`）或 Platform 投影出呈现页，画中画立即出现；资源未到达时显示骨架，到达后必须在 16:9 画布内切换为文件文本、终端尾部、浏览器帧、搜索命中或沙箱页面的紧凑真实内容，不能长期用通用电脑图标代替。Run 结束后，仅当仍有活动浏览器 tab、运行中或 `orphaned` 终端、或仍可读取的呈现页时才保留电脑入口；不再用完成后五分钟的工作记录缩略图维持死画面。

`ChatPreviewContext` 仍是画中画与抽屉之间唯一桥：携带当前 `scope`、电脑抽屉是否打开、当前电脑模式，以及 `openComputer`。当抽屉正在显示浏览器屏幕时，既有 `browserDrawerOpen` 为真，以便浏览器帧继续遵守「同一 scope 只有一个画面消费者」。`openBrowserAssist` 若仍存在，只能作为展开后的明确接管入口，不能由画中画点击隐式调用。

同一 scope 内画中画与展开后的电脑抽屉只能有一个实时画面消费者：抽屉打开后卸载画中画轮询/iframe。记忆、技能、定时任务占用互斥抽屉时，电脑抽屉关闭，但画中画可以保留，因为那些面板不消费浏览器帧或呈现页。

### 屏幕模式

电脑画面一次只显示一块屏幕，由 Platform 投影到当前 `agent_status` / 工作行上的闭世界电脑线索决定，前端不得从消息正文解析 `MEDIA:` 或猜测宿主绝对路径。当前可见的最新电脑类工具选择模式；同一次 Run 内更新只切换这一块屏幕，不并排打开多扇窗口。

- 文件：`read_file` / `write_file` / `patch_file`。只展示当前 Agent 工作区相对路径上的有界 UTF-8 文本和截断标记，不是编辑器。正文只向 `GET /api/agent-previews/file` 请求 Platform 投影的 `workspace_path`；宿主目标只显示脱敏路径与状态，不请求宿主正文。Codex OAuth 的 Responses 参数增量可在执行前建立 `source=draft` 的临时版本：`write_file` 显示完整文件草稿，`patch_file` 只显示并标注替换片段草稿；界面必须显示「未提交」状态，不能把草稿说成已保存文件。聊天 SSE 只携带单调 draft revision，不携带正文；revision 快于正文请求时只允许一个在途请求并排队追赶最新 revision，不能反复中止当前请求而等流变慢后一次跳到大块正文，旧响应也不能覆盖新版本。`write_file` started 到原子落盘之间的 404 是等待态，运行中应有界重试；工具完成或失败时清除草稿并改变 revision，成功后必须读取同一路径的最终工作区快照，即使路径相同，以便 patch 从草稿或旧快照收敛到正式正文。收到的新草稿只渐进揭示已经从受权 endpoint 取得的真实字符，并以有界追赶速度、变更高亮和活动光标表达连续进度；不得把大量行安排在同一个封顶延迟后成批出现，超过逐行 DOM 预算的正文也应使用单个文本画布渐进追赶，而不是整块替换。`prefers-reduced-motion` 时直接显示当前权威版本。其它模型路径的动画只能展示已经读取的真实工作区文本。
- 终端：复用只读 `TerminalPreviewView`。按当前 Run 的终端与仍活动的 `orphaned` 进程组织；`orphaned` 仍显示为“需关注、仍占用”，不能表现为完成或隐藏。主体是接近只读 SSH 日志的深色终端画布：先显示 `$` 与完整脱敏命令，随后显示现有进程预览的真实有界输出，并保持用户未主动上滚时自动跟随末尾。前台短命令若在进程预览捕获前完成，使用最新工作行的有界 `result` 补齐输出与结束状态，不能只显示 command/cwd 参数；该画面不是 PTY，不提供输入、ANSI/curses 仿真或交互。
- 浏览器：复用 `BrowserPreviewView`。无活动 tab 且没有进行中的浏览器工具时不进入该模式；工作记录协助可在 availability 确认前先展开电脑并显示骨架。
- 搜索：`web` / `knowledge` / `search_files`。只渲染 Platform 投影的有界命中列表（标题、URL 或工作区路径、摘要），不能在客户端解析原始 journal，也不能变成文件浏览器。
- 呈现：当前工作区成功写出 `.html` / `.htm`，或本 scope 最新成功回复含 HTML 附件/`MEDIA` 路径时，同一抽屉用沙箱 iframe 渲染该单页；`src` 只能是已认证的 `GET /api/agent-previews/present`。HTML 写入尚在 running 且服务端未确认 `present_available` 时先显示骨架，不提前挂载一个会得到 404 的固定 iframe；同一路径再次完成写入时用工具生命周期或可用性修订强制重新加载。呈现不是 Camoufox，也不为本版本提供工作区静态资源服务器；页面应自包含。本版本不新增 Runtime 工具。

轨道在 `usePreviewAvailability` 仍为 loading 时不得因“尚未确认”而把已有工具线索隐藏成空闲；只有服务端确认没有电脑工作且没有呈现页时才卸下电脑入口。availability 出错时保留已投影的电脑线索并显示可重试错误，不能把轨道电脑按钮误删。

### 浏览器接管与发送

浏览器屏幕默认只读，终端、文件、搜索和呈现页永远不可发送输入：

- 无打开浏览器 tab 且没有进行中的浏览器工具时，电脑不得停在“浏览器尚未运行”的死屏；应回到其它仍存活的模式或关闭电脑入口。
- 资源状态存在但帧、日志、文件正文或呈现页尚未到达时显示骨架/加载态；
- 只有服务端确认对应资源不存在时才显示该模式的空状态；
- 浏览器以低刷新率展示当前 viewport，终端按多个运行进程分组展示；
- 浏览器“接管”必须由用户手势启动，先显示服务端确认的租约状态，再以服务端租期驱动本地到期；短租约也必须让已确认的接管状态可观察，不能因异步渲染竞态直接跳回只读。租约绑定取得时的 `tab_id` 与本地到期时间，不能把旧租约重新解释为轮询后出现的当前 tab。人工输入、取得和释放使用同一客户端串行队列，单调 sequence 只能按队列顺序发送；不得用并发 fire-and-forget 请求让点击、按键、滚动或释放乱序。
- 接管画面使用 Pointer Events；`pointerdown` 后必须取得 pointer capture，并在本地记录、压缩一条单调计时的有限轨迹，`pointerup` 以一个 sequence 提交整条轨迹。`pointercancel`、pointer capture 丢失、失焦、隐藏、tab 变化和卸载必须清除尚未提交的本地轨迹、立即降为只读并尽力 release；服务端已经开始的完整轨迹由 Camoufox 的 `finally` 抬键，不另设无法中断原子轨迹的伪取消协议。拖动期间提供本地指针反馈，不能让远端帧延迟表现为没有响应。接管期间按服务端返回间隔自适应提高 viewport 帧率，连续静止时退避，退出后恢复低频；隐藏页面不得继续获取图片。触摸、鼠标和触控笔共享同一左键拖拽语义，不实现多点缩放、文件选择、剪贴板或任意地址导航。
- 用户在同一 scope 提交新消息时必须先同步降为只读，再等待在途取得、输入及对应释放全部收敛后发送；这段等待不能重复发送已提交 payload，也不能阻塞用户继续编写下一条短消息。结束、窗口失焦、页面隐藏、租约到期、tab 变化、组件卸载或服务端返回租约冲突时立即恢复只读，并对原 tab/lease 做尽力释放。终端预览永远不可发送输入。

HTML 呈现 iframe 必须带 `sandbox` 且不含 `allow-same-origin`；脚本若启用也只能在该不透明源内运行。产品页不得用 `innerHTML` 或非 iframe 方式执行该 HTML，呈现页不得读取父页面 DOM、产品 Cookie 或调用产品 API。文件与搜索内容只按纯文本渲染。

## 通知与账户集成

设置页提供浏览器通知开关。权限只能由用户手势请求；仅在页面已加载完成、用户显式启用、权限为 `granted` 且页面隐藏或失焦时，对任一当前用户可访问 scope 中新持久化完成的 Agent 回复弹一次通知。通知由独立于当前视图和消息数组的轻量完成事件流驱动：事件必须携带单调持久消息 ID、scope 类型与 scope ID；首次连接只建立当前水位，网络重连使用 SSE `Last-Event-ID` 延续该水位。初始 hydrate、历史分页、重复 SSE、切换后首次加载 scope 和当前可见页面不通知；点击通知聚焦页面并通过频道选择或私人视图的正式异步导航动作定位对应 scope，在目标 cache 恢复或请求完成前不能把上一 scope 的消息显示在新标题下。页面保持打开时，隐藏状态继续保持完成事件流；切换频道或切到私人对话、知识库、设置和管理页都不能丢失其它 scope 的完成事件。该能力不是浏览器完全关闭后的 Web Push；页面重新加载后重新建立当前水位，不补发页面关闭期间的回复，非 secure context 时明确显示不可用。

管理面板安全页提供默认关闭的 LAN 监听开关、独立监听地址、直连 CIDR 与可信入口 CIDR 配置。会话 TTL 表单以服务端当前值为准，配置尚未返回时才回退到安全设计中的 7 天出厂默认，并说明 Cookie 会按该时长保存、日常使用会自动续期；续期由 Platform 在响应中重写 Cookie，界面不得自行签发或延长会话。安全页不编辑 Platform 容器 listen host/port，只展示当前进程实际绑定。启用明文 LAN 时必须展示 Cookie、同源与 Web Notification 的 secure-context 风险；界面不能把“已保存”误报为“已通过 TLS 保护”。

私人设置页提供邮箱账户表单、凭据已配置状态、连接测试、立即检查和收信唤醒开关。密码不回填；更新非凭据字段不能清空既有密码。全部可见文案同步三种界面语言。

同一设置页只向具备 `private_agent` 权限的用户提供 Sylver Lining 工作平台连接卡，其他用户不渲染也不请求该私有接口。提供方地址固定为官方入口 `https://devops.sylver-lining.org` 并只作只读说明，表单唯一连接字段是 Personal API Token；界面只提交一次候选凭据，服务端验证成功才显示远端姓名、账号、邮箱、角色和验证时间。Token 输入永不回填，读取只显示已配置状态；重新连接必须再次输入 Token，断开使用确认浮层。连接失败保留既有连接并显示有界错误，不展示远端响应正文、Token 或内部网络诊断；远端身份已经绑定到另一位本地用户时，稳定冲突文案应引导用户联系管理员或改用自己的 Token。

管理员账号列表不把 Sylver 状态并入通用用户投影，也不逐行预取。每个账号的低频操作菜单始终提供独立连接抽屉，打开时才读取目标账号连接；停用或暂时无个人 AI 权限的账号也可查看和断开，任意现存账号均可预配置，实际 Agent 使用仍由账号状态与权限校验。管理员输入 Token 后先只取得无凭据的远端身份预览，界面并排显示本地目标与远端身份；明确确认后服务端重新验证身份才保存。Token 只存在抽屉局部状态，关闭、切换目标和成功后立即清空，永不进入全局 Store、浏览器存储、通知或错误正文。全部可见文字同步三种界面语言。

登录页对认证失败保持统一文案，不能区分账号是否存在。服务端返回登录限流时，界面展示可重试提示并尊重 `Retry-After`，不能在倒计时期间自动重复提交密码。

## 响应式布局

界面必须以动态视口和安全区为约束，不依赖固定桌面宽度。手机上应用外壳、聊天内容、消息气泡、代码块、Composer 和侧栏都必须限制在可见宽度内；长命令、URL、表格和 pre 元素应内部滚动或安全换行，不能扩大根布局。

输入区固定在当前可用视口底部，但不得遮挡消息尾部。“跳到最新”按钮要避开输入区及系统安全区。桌面侧栏展开不能压缩内容到低于组件最小可读宽度。

管理面板是应用主侧栏内的二级布局，不能只根据浏览器 viewport 决定内部列数。只有管理内容容器至少可同时容纳 216px 二级菜单和 840px 正文时才显示常驻菜单，否则切换为紧凑分组选择器。页面标题、说明、主操作和刷新入口必须位于同一页头；一个页面最多保留一个高强调主操作，不能在正文卡片内重复标题和操作层级。

账号等结构化数据在宽屏使用紧凑表格，状态必须同时显示文字和颜色，危险或低频动作收入下拉菜单；窄屏切换为无需横向滚动的列表。账号行桌面高度保持在 64–72px，操作不可换行撑高整行。创建和编辑使用抽屉，手机上占满可用宽度。配置表单、审计工具、会话审计和统计区根据管理页自身的容器宽度降列；宽表格和趋势图只允许在自身区域内滚动，不能扩大页面根布局。

“底层服务”页面是只读健康视图，不是第二套服务生命周期控制器。Platform 只返回 `name`、`available`、`state`、`detail`、`error` 以及缓存新鲜度；不得向浏览器暴露内部 URL、宿主或容器路径、管理来源标记，也不得保留 `managed` 等已失去区分意义的字段。当前状态集合只有 `running`、`unavailable`、`available`、`missing`、`error` 和 `invalid_config`；界面和 i18n 不为旧安装、准备、外部运行或停止流程保留状态文案。

## i18n 与可访问性

界面支持 `zh-CN`、`en`、`zh-TW`，默认根据浏览器语言选择，并保存到 `eap-locale`。翻译 key 是界面契约；新增可见文字必须同时补齐三种语言。用户消息、Agent 输出、工具结果与文件不翻译。电脑画面新增可见字符串必须同时锁定「AI 的电脑 / AI computer / AI 的電腦」与「显示 AI 的电脑 / Show the AI computer / 顯示 AI 的電腦」，不能借用导航「工作区」或只补一种语言。

对话框需要焦点圈定、Esc 关闭和嵌套栈管理；图标按钮必须有可读名称；状态不能只依赖颜色。主题初始化脚本在 React 启动前应用用户选择，避免首屏闪烁。

## 容器管理状态

管理面板中的“自动更新”改为管理器状态页，展示当前/候选/上一 generation、release commit、当前 generation 最近一次成功启用时间、核心服务健康、下载进度、公开 state、operation phase 和最近安全错误。该时间直接来自 Manager 当前 generation 的 `activated_at`；回滚后展示被恢复 generation 原本的成功启用时间，不伪造为回滚操作完成时间。正常状态下可提交检查更新、更新、重启和回滚；这些操作只创建管理器 operation，前端不得自行拼接 Docker 或 Git 命令。

Manager 的数值 `generation` 是并发修改版本，必须单独透传为操作的 `expected_generation`；release `current/target/previous.id` 只用于展示，不能互相替代。RFC3339 `checked_at` 在 Platform 边界规范化为前端可解析的时间，每个 service 的 `status` 规范化为明确的 `available/state`，未知或 unavailable 状态不得默认显示为 ready。

Manager 服务状态区必须逐项呈现当前固定服务目录：`platform`、`agent-runtime`、`camofox`、`searxng`，以及 `firecrawl-playwright`、`firecrawl-redis`、`firecrawl-rabbitmq`、`firecrawl-postgres`、`firecrawl-api`；Manager 自身状态可以并列展示。Firecrawl 的每个当前必需依赖都必须独立展示，不能合并成一个模糊状态，也不能继续展示已退出当前基线的 FoundationDB 项。

候选镜像预拉取和 `waiting_for_tasks` 不阻断其它页面；进入 `updating` 后，全局 `UpdateGate` 禁止使用并显示管理器维护状态。失败时如果 Platform 仍可用，管理页展示 operation id 和使用宿主 CLI 的恢复提示；不得向普通页面泄露 Docker socket、registry 凭据、宿主绝对路径或完整管理日志。

候选对 workspace、Runtime 与 machine marker 的验证属于更新内部步骤；readiness 失败只展示有界 operation 错误并保持旧 generation 可用，不能向普通用户暴露宿主路径、内部 marker 或迁移细节，也不能绕过同一 `UpdateGate` 继续切换。

Manager 状态不可达时不能伪造为 `idle`。管理页必须显示控制平面不可用，禁用保存配置、检查更新、更新、重启和回滚等所有变更入口，不能让用户点击后才收到 400/503；写操作不存在其它回退控制器。

## 验证

组件测试应使用与生产一致的 `eap` 组件前缀、主题、品牌和 i18n Provider，并使用真实 Store 和请求边界覆盖关键生命周期，特别是空数据 selector、迟到响应、移动宽度、维护切换、SSE 重连、首帧加载和电脑画中画/抽屉。电脑画面回归必须覆盖：空闲对话不渲染监视器、工具一开始即出现骨架、画中画保持迷你 16:9 且各模式在数据到达后展示紧凑真实内容、live 画中画从同一 `started_at` 按秒计时且非 live 不继续计时、点击后当前模式填满抽屉标题栏以下区域、Codex 文件草稿的 revision 连续更新且始终标注未提交、草稿正文不进入聊天 SSE、创建文件的 404 从等待态收敛到正文、同路径 patch 刷新、失败/完成清除草稿并切换正式快照、短命令以工作结果补齐终端、个人 AI 与频道共用标题文案、画中画点击只展开只读槽、浏览器与终端共用一个电脑入口、记忆/技能/任务仍独立、展开后卸载画中画、HTML 完成前不挂载且完成后只走沙箱 iframe，以及接管仍须明确手势。工作记录回归还必须证明仅有状态/时间的行不可空展开，文件、终端、搜索和浏览器详情先显示对象与结果且不重复通用字段。品牌回归必须覆盖中性默认、缓存恢复与重验证、非法响应降级、locale/品牌变更后的 metadata/favicon、匿名/维护/错误/Shell 的一致渲染、管理员 revision 冲突和保存后的跨标签页同步；静态构建测试必须证明固定品牌资产不再是发布前提且旧资产会被原子清理。历史回归必须在频道和私人对话分别加载多于一页、离开再返回，并证明 delta refresh 不裁掉已缓存前缀；通知回归必须从保留另一 scope 消息的真实 Store 点击通知，证明复用正式导航、目标加载和消息隔离。业务样式需要绑定组件库公开的 semantic `classNames/styles`，测试不得依赖默认 `ant` 前缀掩盖生产选择器错误。前端 lockfile 必须通过 high 级别依赖审计；传递依赖修复保持最小，不带入无关组件升级。命令见[测试与验证](../development/testing.md)。
