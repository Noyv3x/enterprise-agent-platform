# Frontend

React/TypeScript/Vite builds every surface from [Beautiful UI](https://www.beautifului.dev/), an MIT component library for AI interfaces, used as source rather than imitated (see [组件与视觉系统](#组件与视觉系统)). The [Platform API](../reference/platform-api.md) is the sole frontend wire contract; the browser does not call Runtime or Manager directly.

## Views

- Login and shell: the sidebar's primary items are 个人 AI, 纯聊天模式 (Plain chat, 純聊天模式; the hash keeps `chat` / `chat-<id>`) and 频道, then 管理 and 设置 at the foot. Keep neutral branding, theme and all three locales. Entering the app (a typed or bookmarked address, a new tab, sign-in) opens Personal AI whenever the account may use it, unless the address names a specific chat or channel, which then opens as addressed; reload and back/forward keep the current page. Accounts without Personal AI keep the addressed page, and a bare or unknown address opens their first permitted area (Chat, Channels, then Settings).
- Conversations: durable history, streaming text/thinking and tool activity, uploads and downloadable generated `MEDIA:` files. Attachment cards (ContextCards) show the name and size, a download chip and an image's thumbnail; nothing expands inside the message. 打开 (and a click on the thumbnail) shows the file in the 作品 panel's file mode (below) when its `view_kind` is not `other`. Thinking and tool calls stay visible after the reply finishes and after reload, from the persisted work trace (and, read-only, from older `agent_work` records). Each reasoning block renders the model's available reasoning summary (or raw reasoning text when exposed) as Markdown in secondary trace prose, with bold headlines and its own elapsed-time heading from the block's timestamps; older untimed blocks remain readable without a duration. Empty comment sentinels outside code fences and placeholder-only summaries are hidden. An open block without displayable text shows a quiet, politely announced thinking pulse in place; an empty finished block disappears. Streaming thinking text is not live-announced, and reduced motion stops the pulse. The overall thinking/work heading retains its elapsed time across inserted-message segments. Persisted replies preserve inserted-message segments and channel authors; stopped inputs retain resend. Requests sit immediately before their linked replies, ordered by reply id, followed by the running turn and then truly queued messages. System and unpaired messages retain their id position. There are no live file drafts.
- Steering (插队): while an interactive run can take input, Enter inserts the message into it (when the Platform still finds it eligible) and Alt+Enter sends it after the turn, as its own queued turn labelled 本轮结束后发送; the composer hint shows both shortcuts, and a send menu (the chevron beside send, or a long press on send) offers the same two choices on touch screens. Idle, Enter simply sends. A pending insert appears at the end of the live reply with the after-current-step label, then moves as the same bubble (a short glide) to its delivery boundary between work segments, with a polite announcement; an undelivered insert requeued at turn end glides to the queue the same way. Until the agent has seen it, the author may withdraw (撤回) a queued or pending message: the bubble collapses, its text returns to the composer above any draft (separated by a blank line) and its files return as attachment chips; if the agent read it first, an inline note says so and the bubble stays. Stop cancels the whole backlog, so with queued or pending messages it first asks for confirmation, naming how many will also be cancelled and that they can be resent; otherwise it stops at once. The live reply settles into the persisted reply without remounting: open disclosures stay open and nothing replays its entrance. Only messages newer than the first loaded page play an entrance, and reduced motion makes moves and collapses instant.
- Manual context compaction shows as a status row at its place in the transcript (`after_message_id`), not pinned to the end; only an operation still queued, whose place is not known yet, follows the latest activity.
- Personal computer panel (Manus-style "the AI's computer"): no views to choose. One screen follows the AI step by step; below it the step description (the conversation's tool verbs) with its status (working, thinking, done, failed), a playback bar, the browser takeover action and a collapsed workspace file list/download. The screen is flush with the side panel (desktop `WindowAside` and narrow `Sheet` alike): no inner rounded or shadowed window and no faux-window chrome (traffic lights); its functional rows form a slim flat toolbar (the title tab, or the browser's tabs, and 展开 in a 36 px row; an address row only for URLs and search queries) over the full-bleed screen, and the rows below it are hairline-separated with 12 px side padding (spec shared with the 作品 panel). The screen renders the displayed step by kind: bash, grep, find and ls as a read-only terminal transcript of the run's shell steps up to that step (`$ command`, grep/find/ls as their equivalent commands, output scrolling live from `tool_output`, replaced by the final output at `tool_end`, failures marked); write, edit and read as the file with its path (content grows from `tool_input_delta`, edits as removed/added blocks; a finished edit or write then shows its standard unified patch from `tool_end.details.patch`, or after reload from the work trace's `patch`: hunk headers, old and new line numbers and CodeBlock Diff's +/− tints, with the exact +/− counts in the file row; without a patch, a write keeps showing its new content); browser as the live screenshot with its tabs when it is the newest step of the current run or there is no step, otherwise a page card (url, action, output; screenshots are not kept); web_search as the query and readable results with links; web_fetch as the page's text; schedule, mcp and other tools as an argument summary and the result. Following shows the newest step of the live run (switching when a step begins), else of the run that just ended, else of the latest reply with tool steps (after reload). The playback bar (previous/next, a step scrubber, `n / total`, Live or Back to live/latest) reviews earlier steps; while reviewing, new steps and runs never move the window. Each personal AI tool row in the conversation has "View in computer", which opens the panel on that step. Window content follows the end while streaming unless the reader scrolled up; the expand control opens a larger viewer with the playback bar. Takeover (acquire/release; a held lease makes agent browser actions busy) pins the window to the live browser and pauses playback; handing back resumes following. Reloaded steps come from the bounded `metadata.work` and say when content was clipped. Very long content renders only part with a note; the terminal is `role=log` and only state changes are announced. The conversation's work trace does not show streaming input or output. Channels and chat have no computer panel.
- Artifacts (作品, every scope): what the AI publishes with the `artifact` tool or a viewable `MEDIA:` file (text kinds, DOCX, XLSX, PPTX, PDF; see [product](product.md)).
  - Cards: the live reply shows a card as soon as SSE `artifact` arrives, one per artifact at its newest version; a settled reply shows the same cards from `metadata.artifacts`, also after reload. The stored text keeps the `MEDIA:` line of a file published as an artifact; the reply hides it when it matches an artifact's sandbox path (compared by basename, as attachment lines are). A card has the kind icon, the title, "v3 · 网页", 打开, which opens the panel at the version its message created, and 下载 for that version (`…/versions/{v}/download`, every kind except live previews, which have no files); a live preview's card reads "网站预览" plus its state (等待启动 / 运行中 / 已停止 / 已结束), which follows the stream; after a reload a transcript with live cards fetches the artifact list at once, whose live items carry their `preview`. The work trace and the computer name the tool 发布作品 (查看作品 for `list`).
  - Panel: on desktop a right-side window; personal AI shares it with 电脑 through a SegmentedControl (作品 / 电脑), chat and channels have it for artifacts only, and a header button 作品 opens it everywhere. On phones and narrow windows it is a full-screen Sheet, opened only from a card, an attachment's 打开 or the header. Without an open artifact it lists the conversation's artifacts (`GET /api/artifacts?scope=`, newest update first, kept current by SSE) or guides how to get one. It is flush, like the computer: flat hairline-separated rows over a full-bleed screen, no inner window, card or traffic lights; only the list and notices are padded.
  - File mode: an attachment opened from its card covers the panel's artifact or list until 关闭文件 returns to it (opening an artifact also leaves it; a publish never replaces a shown file). One row: the kind icon, the file name, kind and size, 下载 (the attachment's download URL) and 关闭文件; no versions, source or 刷新. The file shows through `POST /api/attachments/{id}/view` (`{url, kind, expires_at}`, re-minted like an artifact's view URL): `pdf` as an iframe without a `sandbox` attribute (the route's CSP sandboxes it), `docx`/`xlsx`/`pptx` as an iframe `sandbox="allow-scripts"` of the Office viewer page, `image` as an `<img>`, `text` fetched cookie-less (at most 2 MiB, which the view says when the file is larger) into CodeBlock; `other` only offers the download. While a file shows, its card's 打开 reads 已打开 and the artifact beneath is not marked open.
  - Toolbar: a first row with back to the list, kind and title, 刷新 (re-mounts the preview with a fresh token), 新标签打开 (the view URL), 下载 (`…/download`) and 放大 (the ScreenViewer frame, which keeps its FauxWindow card); a second row with 预览 / 源码 (not for the binary kinds `image`, `pdf`, `docx`, `xlsx`, `pptx`), 对比上一版 for single-file text kinds with an earlier version, 桌面 / 平板 / 手机 for web pages (768 and 390 px viewports, scaled down to fit), 圈选 (below) and the version select (vN · time, "最新"); for web pages the page path in a mono address row above the screen; 关闭 on the window.
  - New versions: viewing the latest, the panel moves to the new version with a polite "已更新到 vN"; viewing an older one, it says "有新版本 vN · 查看". On desktop the first publish of an artifact opens the panel at it (taking the shared window from 电脑) unless another artifact or a file is open; a panel the user closed is not reopened for later versions of the same artifact.
  - `web` and `site` previews are an iframe of the view URL (`POST …/view`) with `sandbox="allow-scripts allow-forms allow-modals allow-popups allow-popups-to-escape-sandbox allow-downloads"`, no `allow-same-origin`, and `referrerpolicy="no-referrer"`. The panel re-mints the URL five minutes before the token expires, and again when a hidden tab returns after its timer was throttled.
  - Artifact page helper: pages run in an opaque origin, so Platform injects `/artifact-runtime.js` (source `frontend/artifact-runtime/runtime.js`, dependency-free, minified to `static/artifact-runtime.js` by `npm run build` through `scripts/build-artifact-runtime.mjs`, under 12 KB) as the first script of every HTML page. It installs in-memory `localStorage`, `sessionStorage` and `document.cookie` (the native accessors throw there and are never touched), seeds `localStorage` from the iframe URL fragment `#__eap=<base64url JSON>` and strips it, and posts debounced `{type:'eap-storage', data}` snapshots for the panel to keep per artifact. It records `console.error`/`warn`, uncaught errors, unhandled rejections and failed resource loads in `window.__eapLog` (the first 50 entries, 500 characters each). The panel turns the inspector on with `{type:'eap-inspect', on}`: the page outlines the hovered element, suppresses clicks, and posts `{type:'eap-pick', kind:'element', selector, tag, text, rect, path, scroll, viewport}` on click or `kind:'region'` (`rect`, `path`, `scroll`, `viewport`) on Shift+drag, and `{type:'eap-inspect-exit'}` on Escape. Rects are in document coordinates (`{x,y,w,h}`) and `path` is the page path under the artifact root. The helper only obeys messages whose source is `window.parent`; the panel accepts only messages whose source is its own iframe window (origin `'null'`).
  - Kept page storage: the panel keeps each page's latest `eap-storage` snapshot per account and artifact id (every version and page of it share one), in memory and in its own `localStorage` under `eap-artifact-storage:<user id>:<artifact id>` as `{t, data}` (`t` the last use: saved, or seeded into a frame); an empty, malformed or larger than 256 KB (UTF-8 JSON) snapshot clears what was kept. All kept records together stay within 1 MB: after each use the least recently used ones (unreadable records first) are dropped, so pages never fill the app's own storage. The frame URL carries the kept snapshot as `#__eap=` (base64url of the UTF-8 JSON, no padding) when it is minted or re-mounted (刷新, a version switch, a reload of the app), never on 新标签打开 and never when the URL already has a fragment; later snapshots do not reload the frame.
  - 圈选反馈 (annotate, for people who can post in the conversation): 圈选 in the preview toolbar of `web`, `site` and live pages turns the inspector on (sent again on every frame load) with the hint 点选元素，或按住 Shift 拖动框选区域, an accent ring on the frame, the count 已加入对话（n/5）, 完成, and on phones 去写意见, which closes the sheet. Escape in the page, 完成 or the toggle turns it off. A pick's selector is cut to 500 characters, and a pick whose page path is longer than 500 (Platform's limits) is dropped. Each pick calls `POST /api/artifacts/{id}/versions/{v}/capture` (live: `POST …/live/capture`) with `{path, rect, viewport:{w,h}}` and adds two chips to the composer: the feedback context 「标题 v3 · h2 · 摘录」 (区域 for a region; no version for a live page) and the screenshot (spinner while it renders, then a thumbnail; a failed capture says why and the context still goes). For `markdown`, `code` and `table` the same toggle quotes text: selecting text in the preview shows 引用到对话 under it, which adds the context 「标题 v1 · 引用 · 摘录」 (the quote up to 1,000 characters, path = the entry) without a screenshot. At most five contexts wait; a sixth pick says so and captures nothing. Removing a context removes its screenshot; removing the screenshot keeps the context. Send waits for screenshots being rendered and may carry only feedback; the message body adds `artifact_feedback: [{artifact_id, version, path, kind:'element'|'region'|'quote', selector?, text?, rect?}]` (`version` null for a live page) and the screenshots' ids join `attachment_ids`. The user bubble shows `metadata.artifact_feedback` as chips (title and kind from Platform) that open the panel at that version. Withdrawing (撤回) a message puts its feedback contexts back in the composer with its text and files (its screenshots return among the files, no longer tied to a context), as many as fit under the five; a note says how many did not.
  - Live previews (`live`, personal AI): no versions, source or download. The header shows the service name and a status pill (等待启动 / 运行中 / 已停止 / 已结束) from `GET /api/artifacts/{id}` `preview` and SSE `artifact` events carrying `preview` (the newer one wins). Only an event with `cause:'preview'` (the AI's `preview` call) during a run adds the run's card and may open the panel; `cause:'state'` (stop, resume, 结束预览) only updates the state. The link (`base_path`) stays the same across restarts of the service. Waiting says the site opens once the service runs; running frames `base_path` plus `path` (without its leading slash) in the same sandbox as web pages, with 桌面 / 平板 / 手机, 圈选, 刷新, 新标签打开 and 放大; 已停止 says the site shows again at the same link once the AI starts the service again, and the frame returns by itself when it does; 已结束 (`revoked`) says the link no longer works and the AI can preview the site again. 停止服务 (while running) asks for confirmation, then stops the task (`POST /api/tasks/{task_id}/stop`); 结束预览 (until revoked) asks for confirmation (链接将失效; the service keeps running), then revokes the link (`DELETE /api/artifacts/{id}/live`). Both refetch the preview afterwards.
  - The other kinds fill the panel: `markdown` in the conversation Markdown renderer; `mermaid` as a diagram; `svg` and `image` as an `<img>` of the view URL, where an SVG's scripts never run; `pdf` as an iframe of the view URL, sandboxed by the route's CSP (a `sandbox` attribute would block the browser's PDF viewer); `docx`, `xlsx` and `pptx` as an iframe `sandbox="allow-scripts"` (opaque origin) of the view URL, which is the lazily loaded Office viewer bundle (`frontend/file-viewer/`, built into `static/file-viewer/` by `npm run build`; no React inside the frame) — the same viewer shows Office attachments opened in the panel's file mode via `POST /api/attachments/{id}/view`; `table` (CSV, or TSV by extension; quoted fields may hold the delimiter, `""` and line breaks) as the header row and the first 1,000 rows, with a note giving the total when more exist; `code` in CodeBlock. Text kinds read `…/source`; a file cut off at 2 MB says so.
  - 源码 shows the file in CodeBlock. A site lists its files (the entry first, marked 入口) beside the code, or in a Select when the panel is narrow; picking a file loads its source. Nothing is read before the file list arrives, and a file whose MIME Platform does not serve as text (`text/*`, JSON, XML, JavaScript, web manifests, SVG) says so instead. 对比上一版 diffs the entry's lines against the previous version in the browser (three lines of context; past 1,500 changed lines the changed middle shows as replaced) in CodeBlock's Diff variant; versions with the same text say so.
  - Mermaid, in the panel and for ```mermaid fences in messages: the library loads with the first diagram as its own chunk, never in the app bundle, and renders with `securityLevel: 'strict'` in Mermaid's `base` theme drawn from the painted Beautiful UI tokens (light or dark, brand accent), again when the theme changes. A message fence draws once its block is complete (code while it streams), in a card whose 源码 toggle shows the source. A diagram that does not parse, or a library that does not load, falls back to the code block with a note.
  - A diagram never fetches anything, as message images never do. `%%{init}%%` directives and config frontmatter are dropped, and the theme, CSS, font, sanitizer and security keys are Mermaid `secure` keys. A source that would load an image or stylesheet is refused before it renders and shows as code with a note: an image shape (`img`), a sequence actor icon (both also checked on the parsed diagram), CSS `url()`/`@import`/`image-set()`, a loading HTML tag in a label, or a CSS escape in a style statement. Label HTML loses loading tags and `src`/`href`/`style` attributes, and the finished SVG loses images, outside links and external `url()`.
- Personal AI subagents and background tasks (`bg-<n>`, see [product](product.md)): state comes from `GET /api/tasks` when the conversation loads plus SSE `task` events; a task that already ended never returns to running from an older snapshot. In the work trace a `task` row nests one row per subagent it started (matched by `created_by_tool_call_id`): name, a type badge (调研 for `scout`, 执行 for `task`), a status ring, the current activity, elapsed time and tokens; selecting a row opens the subagent sheet (its work trace, its report as Markdown, Stop with confirmation). A bash row that moved to the background (tool_end `details.background`, else its "Running in the background as bg-n" result) shows a `后台 · bg-n` chip with the task's live status that opens its output. `job`, `wait` and `task` rows read as 管理后台任务, 等待后台结果 and 分派子任务. A `task_notice` system message is a compact status row (「后台任务完成：bg-12 pytest · 退出码 0」, one line per task, each opening the task) before the AI's turn; notices marked `skipped` are hidden. The computer panel lists running tasks first, then recent ones, in 后台任务 above 工作区文件; a process opens a read-only terminal-style output viewer (AgentScreen's expanded-viewer frame) that long-polls `/api/tasks/{id}/output` only while open, from the retained tail, and says when earlier output was dropped; an agent opens its sheet. Stopping always asks first. Only task state changes are announced (politely), never activity or output.
- 纯聊天模式 (Chat): selecting it in the sidebar opens the latest chat, or a blank one when there is none. Only while this area is open (`route.view === "chat"`, desktop, collapsed rail and phone drawer alike) does the sidebar show its controls: 新聊天 below the primary items (separated by a hairline), the 聊天记录 list (search, rename, delete) above the channel list, and on the collapsed rail the chat search button beside 新聊天. Other areas show none of them. Deleting the last chat moves focus to 新聊天. The header of a blank, loading or missing chat reads 纯聊天模式; an open chat's header is its title. A new chat is created with the localized placeholder title 新聊天; after its first message Platform may replace it with a generated title (SSE `conversation_title` `{id, title}`), which the shared chat list applies at once, so the sidebar row and the header change without a reload. The composer and header show no model; chat uses the account's model set by administrators. Each chat has a working directory in the user's shared lightweight sandbox; bash can access that user's other chat files.
- Admin: users (each assigned one model policy group, which replaces any per-account model or thinking field), permission groups (their permissions include 安装技能和连接器, `install_extensions`), model policy groups (策略组: a label, an identifier fixed at creation, a 主模型 — a model from the live catalog or 系统默认 plus a thinking depth 自动/关闭/极低/低/中/高/超高, where 自动 is offered only for an explicitly chosen GPT-6-family model and is otherwise disabled with its reason — serving 个人 AI, 纯聊天模式, 频道 and every subagent, and a Judge 模型 — a catalog model or 与主模型相同 plus a thinking depth without 自动 — that titles chats and judges each turn's difficulty when the main depth is 自动; new groups start at 主模型 {系统默认, 中} and Judge {与主模型相同, 低}; the table shows 账户数, 主模型 and Judge 模型; a configured model the catalog no longer offers stays visible as unavailable; every save sends the whole list; a group with accounts, or the last group, cannot be deleted), skills, connectors, branding, models/Codex OAuth, system/update controls and token usage including cache-hit ratio (recent records show each record's 来源 and 用途 — 对话, 压缩, 子智能体, 标题 or 难度判断 — and the thinking depth a run used).
- Admin → 技能: a records table with two views. 组织技能: install from an uploaded ZIP or `.skill` file or a link, with 可使用的权限组 chosen as 所有人 or specific permission groups; selecting a row opens its sheet (the assignment and an enable switch saved together, 从链接更新 for link sources, delete with confirmation, the skill's content). 内置技能: an organization-wide switch per skill.
- Admin → 连接器 (`#admin/connectors`): a records table with three views.
  - 连接器: the organization's remote MCP connectors with status, URL, authentication, credentials (每人授权 or 共享凭据) and 可使用的权限组 (所有人 or chosen groups). 添加连接器 and a row's 编辑 open the same form: name (fixed after creation), display name, URL, transport (自动 is Streamable HTTP, whose version Platform negotiates; SSE（旧版） for legacy HTTP+SSE servers), authentication (无需认证, 请求头, OAuth), credentials, groups and an enable switch, all saved together. Header values are entered only for a shared connector; a per-user one declares header names and each person fills in their own. OAuth adds an optional pre-registered client (client ID, a write-only secret, scopes) with the redirect URI Platform reports. The row's sheet has the status and last error, 连接 / 重新连接 / 断开 for shared OAuth (the same popup as conversation cards; `oauth_registration_required` points to the pre-registered client), 测试连接, the tool list with a switch per tool for everyone, and delete with confirmation.
  - 调用记录: the audited calls (`GET /api/admin/mcp/calls`, latest 200, filterable by connector): tool, connector, account, status, duration, scope and time (`at` is epoch seconds, sorted numerically, newest first); arguments and results are never shown because they are never stored.
  - 内网访问: the hosts and CIDR ranges connectors may reach on private addresses, one per line; a refused entry shows Platform's message.
  - When `oauth_warning` is `https_required`, a notice above the table (and in OAuth forms) explains that sign-in needs an HTTPS public address.
- Settings: kept account/preferences behavior with shared branding/theme/localization, on a 通用 tab (`#settings`). It shows no model, model policy group or thinking depth. Accounts with Personal AI or Chat also get a 技能 tab (`#settings/skills`), the catalog of Personal AI (or of Chat when the account has no Personal AI):
  - three groups, 个人 / 组织 / 内置, with one search; 个人 appears only for Personal AI;
  - each row shows the name, description, a source tag (内置, 组织, 上传, 链接, AI 创建, 已迁移, or 工作区 for a skill without an install record), the version and any warnings, and has an enable switch (the user's preference); link-installed personal skills have 从链接更新, and personal skills a delete with confirmation;
  - selecting a row opens a sheet with the source, version, warnings, SKILL.md rendered as Markdown (frontmatter hidden) and the file list;
  - 安装技能 opens a dialog for an uploaded ZIP or `.skill` file or a pasted link, noting that the personal AI can install skills too; an installed name offers 替换, and a package holding several skills asks which one;
  - after an install, update or delete the list reloads from Platform, because a personal skill hides an organization or built-in skill of the same name and deleting it brings that one back; an update refused because the skill at the link now has another name (`skill_update_renamed`) says so and names the new skill;
  - without `install_extensions` the install, update and delete controls are hidden and a note explains that personal skills are not loaded.
- Settings → 连接器 (`#settings/connectors`), for accounts with Personal AI or Chat (the scope as for 技能; Chat lists remote connectors only):
  - 我的连接器 (shown with `install_extensions`, or when the account has some) and 组织 groups. A row shows the label, name, source tag (已导入, AI 添加, 已迁移), status (已连接, 就绪, 需要登录, 需要重新授权 when the server refused a sign-in it had accepted, 需要填写密钥, 出错, 已停用, 待确认), kind and tool count, and the last error. Personal rows have an enable switch; organization rows a 连接, 重新授权 or 填写密钥 shortcut when the account's own sign-in or keys are missing.
  - 待确认 (`pending_confirmation`): a connector the AI or an import created does nothing until the user confirms it. Its row shows where it connects (the URL's origin only, or the command line for a local program) with 查看并确认 instead of a switch; its sheet names the source (AI 添加 / 导入) and the destination in a warning, and offers only 确认并启用 (`POST /api/mcp/connectors/{id}/confirm`, which also turns it on). Connect, 测试连接, 你的密钥 and the tools appear after confirmation.
  - 添加连接器: 远程服务 (URL, transport 自动 / SSE（旧版）, authentication 无需认证 / 请求头 / OAuth with header name and value rows) or, for the personal AI only, 本地程序 (command, arguments one per line, working folder, environment variable rows). The form checks the name slug, duplicates, the URL and the command before sending. After adding, the sheet opens on the new connector and says what is left (sign in, or keys).
  - A connector's sheet: status and last error, 连接 / 重新连接 / 断开 for OAuth the account holds (personal, or per-user organization), 测试连接 (server, version and tool count), 你的密钥 for the account's own header or environment values, details, and the tools (read-only tagged 只读; switches on personal connectors; read-only on organization ones). Personal connectors add 编辑 (removing a stored key deletes its value) and delete with confirmation. An upstream auth failure (HTTP 409 `needs_auth` or `credentials_rejected`, from 测试连接 or the tool list) reads as 需要重新授权, with 重新连接 for OAuth or a request for new keys; `confirmation_required` asks to confirm first.
  - Secrets: every value input is a password field that starts empty, labelled 已设置 or 未设置 from `secrets_set`; an empty input keeps the stored value, only typed values are sent, and saved values are never shown again or kept in the page.
  - Import: 导入配置 opens a dialog to paste a `claude mcp add` / `codex mcp add` line or a config snippet, or (when Platform found any) pick a detected workspace file; the result lists the created connectors (each to be confirmed) and what each still needs, and the skipped entries with their reasons (a name already in use, a local program outside the personal AI, or Platform's message for an invalid entry). Detected files (`GET /api/mcp/import/detected`) appear in a dismissible banner with 查看并导入; nothing is added until the user imports. The banner drops files whose servers were all imported.
  - OAuth popup (shared with the conversation cards): opened inside the click as `about:blank`, cut from this window (`opener = null`), then pointed at the authorize URL, which must be https (http only on loopback) or the popup closes with an error. The result arrives only over the `mcp-oauth` BroadcastChannel (same origin by construction): `mcp-connected` for that connector id settles it, `mcp-connect-failed` shows its error with 重新连接; a popup closed without a message re-reads the status; a blocked popup offers the sign-in link (`rel="noopener noreferrer"`). The list re-reads when the page becomes visible again.
- Channels: a channel manager's channel sheet has a 连接器 section listing the shared organization connectors the channel may use (`GET /api/channels/{id}/mcp`, a reduced view with the URL's origin only), each with a switch that saves the whole set at once (`PUT`); with none it explains that an administrator adds shared connectors in 管理 → 连接器.
- Composer `/` menu: the conversation scope's enabled skills (Personal AI, the channel, or Chat) follow the commands, tagged 技能. They are listed only while the `/` token starts the message, because Platform reads `/name` only there; picking one puts `/<name> ` at the start of the message. The work trace and computer panel name the `skill` tool's actions 安装技能, 更新技能, 删除技能 and 查看技能 (list and info).
- Composer `/` menu, MCP prompts: after the skills come the scope's MCP prompts (`GET /api/mcp/prompts?scope=`), named `/<connector>:<prompt>` and tagged with the connector's label; they can be picked anywhere in the message. Picking a prompt with arguments opens a small form (required arguments marked, empty optional ones left out); 插入 renders it through `POST /api/mcp/prompts/render` and adds the text below the draft for review. Nothing is sent, and a prompt without arguments is inserted at once. When the connector refuses its sign-in (409 `needs_auth`) or keys (409 `credentials_rejected`), the form or composer says to reconnect or update it in 设置 → 连接器.
- MCP cards in the conversation (connector text is untrusted and shown as plain text only):
  - `mcp_action_required` (the AI added or connects a connector): before any input the card shows where the credentials go, because a label is free text whoever adds a connector chooses: the host of a remote connector's URL origin in monospace (with 未加密连接 for http), or the command of a local one, and who added it (由 AI 添加, 从配置导入, 手动添加). A connector the AI or an import added (`pending_confirmation`) first offers only 确认并启用 (`POST /api/mcp/connectors/{id}/confirm`) with a note to check that address; confirming unlocks every card of that connector, and a card that asked only for confirmation (`kind: 'confirm'`) then reads 已确认并启用. Then 连接 opens the connector's OAuth sign-in in a popup, opened inside the click so popup blockers allow it, and waits for the callback page's `mcp-connected` message on the same-origin `mcp-oauth` channel (that connector's id); a closed popup is checked against the connector's status, a blocked one offers the sign-in link, and a failure (such as `oauth_registration_required`) shows in the card with 重新连接. 填写密钥 opens password inputs for the missing keys inside the card, below the destination and the reassurance text; 保存 sends them to `PUT /api/mcp/connectors/{id}/credentials` and they never enter the conversation. A card stays after its run until it is handled and closed, or dismissed with 稍后.
  - `mcp_elicitation`: the connector's message and, for the user who started the run, a form drawn from the requested schema as is (strings with their email, link and date formats, numbers, integers, switches, single and multiple choices; required fields, length and range limits checked before sending) with 提交 / 拒绝 / 取消, or for a link request the destination host, 打开链接 (http and https only) and 已完成 / 取消. A countdown shows the time left; at zero the card reads 已超时 and offers no controls, because Platform cancels it, and nothing is ever answered automatically. Everyone else sees the message and that an answer is awaited. The card settles as 已提交, 已拒绝, 已取消, 已超时 or 请求已失效 (answered elsewhere), and leaves with the run.
  - The work trace and computer panel name a connector tool `mcp__<connector>__<tool>` 「调用 <label> · <tool>」, with labels from the prompts list (the connector name when unknown), and the `mcp` tool's actions 查看连接器 (list, describe), 调用, 读取资源 (list_resources, read_resource), 添加连接器, 导入配置, 删除连接器, 请求连接, 启用连接器 and 停用连接器.

## State and behavior

Use Platform history and its stream contract, not Runtime transcript export, as the UI source. Display failed/interrupted work honestly and let the user resend; never silently replay it. Old messages remain readable, including old metadata, without restoring removed actions.

Remove memory management panels, approvals, execution-review/needs-review controls, todo views, drafts, Telegram/mail and learning-review UI. AGENTS.md is a file managed with normal agent tools, not a separate panel; skills have the panels above. Subagents and background tasks exist for the personal AI only; channels and chat show none of their controls.

Server authorization remains authoritative even when controls are hidden. Preserve user input and reading position during streaming, navigation and locale/theme changes. Static assets ship with Platform: index is no-cache, hashed assets immutable, with available gzip/Brotli variants.

- Chat lists are scoped to the authenticated account. Logout/session expiry invalidates cached and in-flight results. Deleting a chat permanently deletes its working-directory files; confirmations state both consequences.
- Keep composer text and uploads when the first activity changes an empty conversation into a thread. Resend belongs to the originating stopped user request, not assistant completion order.
- Pasting (Ctrl/⌘+V) attaches the clipboard's files and images, read from its items with the file list as fallback; an unnamed clipboard image is uploaded as `pasted-image-N.<ext>`. In a conversation with a composer this works wherever focus is, except inside another text field or a dialog, and returns focus to the composer.
- Switches inside a form change drafts only; saving requires the form's explicit submit action. A switch on a list row (a skill preference, a built-in skill's organization-wide switch, a connector, a connector tool, a channel's connector) is its own action and applies at once.
- Browser tabs can be inspected without takeover. Expanded computer viewers sit above their parent sheet but below their popovers; Escape closes only the innermost layer.
- Malformed chat hashes follow the unavailable-route path. Disclosure IDs are unique per component instance, and every mobile sidebar selection dismisses navigation, including the current route.

## Branding

Use neutral defaults (`Agent Platform`, `Agent`), shared theme tokens and same-origin versioned logos. Branding changes affect display, not technical identifiers, paths or permissions. Do not load third-party fonts/images as fallbacks. Field validation and public branding shape belong to the [API](../reference/platform-api.md).

## 组件与视觉系统

### 设计原则

- 这是企业内部工作界面：不用宣传语、装饰性大标题或大片留白。
- 每页一个功能标题。说明文字只讲用法、权限、限制和真实状态。
- 同一种状态全站只有一种表达：
  - 细环表示正在进行；
  - 勾表示完成，警告标记表示失败；
  - 加载状态用像素网格动画加真实标签；
  - 分类标记（如"公共"）用图标，不用状态点。
- 权限、风险、引导、错误提示和危险操作确认不能为了简洁而删掉。保存按钮留在所属表单内。

### Beautiful UI

[Beautiful UI](https://www.beautifului.dev/)（MIT，源码 <https://github.com/slev12397/beautiful-ui>）是一个面向 AI 界面的前端组件资源库，也是全站的设计规则。界面直接使用它的源码，不再自制近似版本或另起一套设计层。源码、改编说明和许可在 `frontend/src/components/ui/beautiful/`（`NOTICE`），许可文件随 `public/licenses/` 分发。

- 来源：`foundation.css` 是上游 `app/globals.css` 的通用基础（设计值、浅色/深色、基础规则、间距工具、动画关键帧）；`atoms/` 是上游原子组件；`primitives/` 是上游组件，各组件的专属样式跟组件放在一起。
- 改编只允许：演示数据和定时脚本换成真实数据与回调；接入三种语言和无障碍；付费图标（Central Icons）换成开源图标；去掉远程图片、音效和营销内容。标记结构、类名、设计值、圆角（标签 6、控件 8、卡片 10、窗口 14）、细线边框、阴影和动效保持上游原样。

### 排版、颜色与可访问性底线

- 字体：随静态资源分发 Inter 和 JetBrains Mono 的拉丁字符部分，不请求第三方字体；中文、中文标点和其它字符使用系统字体。等宽字体只用于代码、命令、时间和标识。
- 颜色：使用 Beautiful UI 的中性冷灰语义色，浅色、深色两套（`.dark`）。主操作按钮和开关的开启态是墨色；品牌色用于发送按钮、链接、焦点和少量强调；导航选中态为中性灰。
- 对比度：所有文字在其所在底色上至少 4.5:1，包括品牌色文字和状态色。状态不能只靠颜色区分。
- 触屏和窄屏上所有可点区域至少 44px。
- 系统开启高对比度（强制颜色）模式时，依靠阴影区分的表面要补上实线边框。
- 按钮文案按原样显示，不在中文字之间插入空格。

### 动效与阅读连续性

- 动效只用来说明位置和状态变化，不做装饰性入场、弹跳或主题渐变。切换主题时颜色直接切换。
- 内容在提交后变高时（展开工作过程、延迟排版、画中画留白），停在底部的读者继续跟随最新内容；正在往上翻的读者保持当前位置，也不增加未读数。
- 切换对话、加载更早的历史、流式输出都立即收敛，不制造额外的滚动动画。
- 工作过程运行中只有标题文字的微光、尚无可显示摘要的思考块的轻微脉冲和步骤细环的旋转，不做多行持续动画。
- 工作过程的展开和收起（整段工作、工具组、单个工具详情）统一为 300ms、`ease-out-strong` 缓动；收起后高度真正归零。左侧细线贴着内容框伸缩，不靠测量高度追赶内容。
- 只有真正新出现的行才播放入场动画：正在进行的工作里新到的思考、步骤、工具行和改动标签。恢复的历史和已结束的回复原样出现，不重放入场；回复结束时的操作栏淡入，只发生在刚流式输出完的那条回复上。
- 流式输出每个画面帧最多提交一次；已经结束的 Markdown 段落不再重新解析和渲染，只有正在增长的末尾段落更新。计时只刷新计时文字本身，不重绘整段工作过程。
- "减少动态效果"设置实时生效，不能因此刷新状态、丢失输入或关闭面板。此时动画和过渡的延迟也一并取消，错开出现的内容立即出现。
