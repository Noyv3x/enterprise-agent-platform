# 0004：可配置品牌与中性运行身份

- 状态：accepted
- 日期：2026-07-31
- 更新：2026-08-01

## 背景

产品需要作为可独立供应的软件部署。源码维护方或部署方的名称、Logo、颜色和 Agent 自称不能固化到界面、提示词、通知或离线页面。可变品牌也不能成为文件、容器、权限或更新协议的一部分。

## 决定

品牌是部署后由管理员管理的业务配置。产品名称、Agent 显示名、颜色与受限图片只影响展示；未配置时使用中性名称和图标。匿名登录、认证后界面、通知、导出标题、Agent prompt、维护页和错误页消费同一公开品牌投影或中性降级值。

内部运行身份是固定、不可配置的机器协议。Manager、systemd unit、配置和数据根、Compose project、network、环境变量、label、Cookie、数据库 marker、workspace/session identity 与 release asset 都只使用当前 `agent-platform` 技术命名空间。品牌值不能派生、覆盖或迁移这些对象。

当前仓库、安装器、发布物和运行时只支持这一套技术身份与数据基线。不保留旧身份发现、双写/双读、在线命名空间迁移、迁移 helper、阶段发布或部署回执协议。已有部署若需要从其它布局导入，由操作者在停机、备份和完整校验下执行一次性外部转换；转换程序不进入普通产品发布或后续兼容层。

## 后果

- 同一发布物可由不同部署独立设置品牌，无需重建镜像；
- 品牌输入作为不可信公开文本和图片验证，不能成为 prompt 指令；
- Manager 无法读取 Platform 时仍可生成中性维护页；
- 改变显示品牌不会移动数据、重命名容器或使用户登出；
- 运行、更新和恢复只有一套路径，历史部署细节不能重新获得执行能力。

## 替代方案

构建时替换字符串和图片会制造部署专用镜像；让品牌派生技术标识会使每次改名成为数据迁移；永久接受多套内部身份会扩大测试和恢复状态空间。以上方案均不采用。
