# 0001：文档是唯一设计真相源

- 状态：accepted（2026-09-26 修订）
- 日期：2026-07-21

## 背景

仓库规则曾分散在根 README、组件 README、`AGENTS.md`、`CLAUDE.md`、安全审计和代码注释中。同一个设计被重复描述，配置、模型、超时和部署行为在实现变化后常常留下过期的说明。

代码只能说明当前的实现，无法表达产品意图、被否决的方案和跨组件的规则。但只声明"先写文档"，也阻止不了文档和实现长期漂移。

## 决定

`docs/` 是 Agent Platform 的唯一设计真相源：

1. `design/` 定义产品行为和架构规则；
2. `reference/` 定义当前的配置、协议和数据布局；
3. `operations/` 定义部署与更新流程；
4. `development/` 定义实现、验证和文档的写法；
5. `contracts/` 保存需要由代码和测试共同使用的精确机器值；
6. `decisions/` 记录重要选择的理由。

- 行为、接口、配置或持久格式变化时，先改规范或契约，再改代码，最后更新测试、生成的代码和操作说明。
- 自动检查只验证机器契约与生成代码一致、文档链接有效；行为与设计是否一致由审查和验收证明。
- 根 README 和组件 README 只保留项目入口、最短启动命令和文档链接。`AGENTS.md` 是编码 Agent 的通用行为入口，只规定文档驱动、范围控制、验证和安全操作，不记录代码库事实，也不成为第二份设计。

## 修订记录

- 2026-08-13：允许工具专用的兼容入口通过单一引用复用 `AGENTS.md`。
- 2026-09-20：撤销"仅凭 Git diff 强制代码和文档一起改"的检查及其快照机制——碰过文档不能证明语义同步，反而诱发无意义的追加。移除根目录的 `claude.md`。
- 2026-09-26：
  - 文档只写行为、规则、契约和理由，不写实现细节，改用正常可读的写法。原因是文档写到了组件和样式层面，导致大部分修 bug 和重构的提交都要连带改文档。
  - 删除 `docs/domains.json`（逐文件的代码归属登记表）：它只验证"登记了没有"，不验证内容，维护成本高而收益很小。机器契约的清单移到 `scripts/docs_sync.py` 的 `CONTRACTS` 中；链接检查新增标题锚点验证。
  - 删除从未创建过的 `audits/` 目录的约定。

## 后果

优点：

- 产品意图、运行契约和实现边界有统一的入口；
- 精确值可以机器校验，减少复制造成的漂移；
- 审查时可以先判断设计是否变化，再判断实现是否完整；
- 修 bug 和重构通常不需要改文档。

成本：

- 行为或契约真正变化时，需要维护相应的文档；
- 文档的组织和内容本身需要审查；
- 外部编码工具不一定自动读取 `docs/`，因此根 README 和 `AGENTS.md` 必须提供醒目的入口；
- 自动检查不能证明文字内容正确。

## 例外

- 修 bug、内部重构、补测试和纯文档维护可以独立交付，不为了门禁制造文档或代码改动。
- 机器契约没有例外：所有登记的生成代码必须逐字节一致。
- 紧急安全修复可以先阻断漏洞，但同一次交付中必须补齐规范和测试，不能因为紧急就让实现永久成为第二套真相源。
